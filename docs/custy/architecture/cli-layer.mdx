## Overview

The CLI layer owns the public command tree and converts user input into the
typed values consumed by core coordinators. It should describe behavior and
assemble dependencies, while Git, changelog, release, backup, cleanup, and file
mutation logic remain outside command callbacks.

<Section title="Execution Variants">

- Most validation, Git-operation, backup, cleanup, version, changelog, and Run
  callbacks assemble a workflow engine and a registered pipeline.
- `custy init` enters the pipeline through a specialized initialization step,
  which delegates to `InitMain` and its builder and scaffold service.
- Branch cleanup has a specialized handler and service behind the command
  boundary.
- The workflow command group is experimental and currently has a documented
  step-registration mismatch.

</Section>

---

<InfoBox variant="warning" title="Global context and workflow config are different">

`AppContext` is the Typer-scoped holder for global flags and raw runtime input.
`WorkflowConfig` is the core engine's construction model. Command callbacks
must map supported values deliberately; a field existing on AppContext does
not guarantee that every builder or command transports it correctly.

</InfoBox>

---

<Section title="Presentation Responsibilities">

The CLI layer uses `app/ui`, `app/theme`, and `app/utils/logging.py` for the
shared Rich console, panels, progress, exception rendering, banner, colors, and
rotating logs. Core pipeline and initialization modules also call some of these
presentation helpers, so terminal presentation is currently shared across the
CLI and orchestration layers rather than isolated behind one interface.

</Section>
