## Overview

Changelog generation depends on local repository history and the files selected
by the resolved Custy configuration. Confirm these inputs before writing the
project changelog.

<InfoBox
    variant="tip"
    title="Review repository state first"
>

Use `git status` and inspect the existing changelog before generation. A clean or
understood working tree makes the resulting diff easier to verify.

</InfoBox>

<Section
    title="Recommended Preflight"
>

<Terminal>

{`git status
git tag --list
custy --dry-run changelog generate`}

</Terminal>

Project configuration is optional because Custy provides defaults, but running
`custy init` first makes templates and behavior easier to inspect and customize.

</Section>

<InfoBox
    variant="note"
    title="Remote access is optional"
>

Remote access is not required for local generation. Remote comparison URLs can
still depend on correctly configured repository-link settings.

</InfoBox>
