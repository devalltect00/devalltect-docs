## Overview

The generator resolves configuration once, transforms repository history into
structured releases, and writes the resulting Markdown artifact only after the
content is ready to render.

<InfoBox variant="info" title="The progress bar covers history collection">

The progress counter completes after Custy processes `Unreleased` and every
tagged release range. Release behavior, sorting, template rendering, and the
normal-write or dry-run-preview decision still follow.

</InfoBox>

---

<InfoBox
    variant="info"
    title="Also used by larger profiles"
>

Changelog generation is an internal stage of public profiles such as
`custy run commit`, `custy run release`, and `custy run full`.
The standalone command remains `custy changelog generate`.

</InfoBox>

---

<Section
    title="Failure Behavior"
>

If collection, parsing, template resolution, or rendering fails, correct that
stage before rerunning the generator. Inspect the working-tree diff to determine
whether an earlier changelog artifact already exists.

</Section>
