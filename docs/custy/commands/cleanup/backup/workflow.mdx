## Overview

Backup Cleanup follows a predictable sequence to safely remove obsolete backup
files while preserving the newest backups according to the configured
retention policy.

No project source files or Git metadata are modified during this workflow.

<Section
    title="Workflow Stages"
>

<WorkflowStep
    title="1. Resolve Cleanup Settings"
>

Custy determines the effective cleanup configuration by combining
command-line arguments, your project's `config.toml`, and built-in defaults.

This includes:

- cleanup target
- retention count

</WorkflowStep>

<WorkflowStep
    title="2. Scan Backup Directories"
>

Custy searches the configured backup directories for backup files matching
the selected cleanup target.

Depending on the selected type, this may include:

- commit backups,
- tag backups,
- or both.

</WorkflowStep>

<WorkflowStep
    title="3. Preserve the Newest Backups"
>

The discovered backup files are ordered from newest to oldest.

Custy preserves the configured number of recent backups before selecting
older backups for removal.

</WorkflowStep>

<WorkflowStep
    title="4. Remove Old Backups"
>

Only backup files exceeding the configured retention count are deleted.

Recent backups remain untouched.

</WorkflowStep>

<WorkflowStep
    title="5. Finish"
>

Custy reports the cleanup summary and completes the operation.

No Git branches, commits, or tags are modified.

</WorkflowStep>

</Section>

Backup Cleanup is also executed automatically by several Custy workflow
pipelines.

In those cases, the same cleanup process occurs without requiring a separate
manual command.

</InfoBox>

<Section
    title="Workflow Characteristics"
>

Backup Cleanup is designed to be:

- deterministic,
- repeatable,
- configuration-driven,
- non-destructive to project source files,
- independent of Git operations.

This makes it suitable for routine maintenance during development and release
workflows.

</Section>
