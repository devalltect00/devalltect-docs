## Overview

Branch Cleanup removes Git branches that satisfy the cleanup rules configured
for your project.

Unlike Backup Cleanup, this command operates directly on your Git repository.

To minimize the risk of accidental branch deletion, Custy applies multiple
safety checks before removing any branches.

Only branches matching the configured cleanup filters are considered.

---

<InfoBox
    variant="warning"
    title="Branch Cleanup Modifies Your Git Repository"
>

Branch Cleanup permanently removes local Git branches that satisfy the
configured cleanup rules.

Always review your configuration before executing the command.

Custy automatically protects important branches such as:

- `main`
- `master`
- `develop`

These protected branches are never removed by Custy.

</InfoBox>

<Section
    title="Safety First"
>

Branch Cleanup is intentionally conservative.

By default:

- no branch prefixes are configured,
- no branches are selected,
- no branches are deleted.

Projects must explicitly configure which branch prefixes may be cleaned.

This prevents accidental deletion immediately after installing Custy.

</Section>

---

<InfoBox
    variant="tip"
    title="Configuration Driven"
>

Branch Cleanup behavior is controlled entirely by your project's
`config.toml`.

You decide:

- which branch prefixes may be cleaned,
- whether merged or unmerged branches are eligible,
- whether age filters should be applied,
- and which branches should remain protected.

</InfoBox>

---

<Section
    title="Workflow Integration"
>

Branch Cleanup is available as the standalone public command:

```bash
custy cleanup branches
```

The internal `cleanup_branches` profile is intentionally **not** included in
Custy's public automated release workflows and is not accepted as a public Run
argument.

This ensures that branch removal always remains an explicit user decision.

</Section>
