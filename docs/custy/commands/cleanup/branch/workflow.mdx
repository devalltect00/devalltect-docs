## Overview

Branch Cleanup follows a multi-stage evaluation process before deleting any
Git branches.

Rather than deleting branches immediately, Custy progressively filters the
available branches until only eligible candidates remain.

This layered approach helps minimize the risk of accidental branch removal.

<Section
    title="Workflow Stages"
>

<WorkflowStep
    title="1. Resolve Cleanup Configuration"
>

Custy determines the effective cleanup settings by combining:

- command-line options,
- project configuration,
- built-in defaults.

These values determine how the remaining workflow behaves.

</WorkflowStep>

<WorkflowStep
    title="2. Inspect Local Branches"
>

Custy retrieves the local Git branches and gathers the information required
to evaluate each branch.

This includes branch names, merge status, and commit dates.

</WorkflowStep>

<WorkflowStep
    title="3. Apply Cleanup Rules"
>

Each branch is evaluated against the configured cleanup rules.

These include:

- configured branch prefixes,
- merge status,
- optional age filters,
- protected branch rules.

Only branches satisfying every applicable rule remain eligible.

</WorkflowStep>

<WorkflowStep
    title="4. Remove Eligible Branches"
>

Custy deletes only the branches that remain after all filtering stages have
been completed.

Protected branches are never removed.

</WorkflowStep>

<WorkflowStep
    title="5. Report Results"
>

Custy displays a summary showing the outcome of the cleanup operation.

Depending on the project configuration, this may include deleted branches,
skipped branches, or a message indicating that no cleanup was required.

</WorkflowStep>

</Section>

<InfoBox
    variant="tip"
    title="Safety by Design"
>

If no branches satisfy the configured cleanup rules, Custy completes
successfully without deleting anything.

This is an expected outcome rather than an error.

</InfoBox>

<Section
    title="Filtering Pipeline"
>

Conceptually, every branch passes through the following evaluation stages:

1. Prefix filter
2. Merge status filter
3. Age filter (if configured)
4. Protected branch check

Only branches that successfully pass every stage are eligible for deletion.

</Section>
