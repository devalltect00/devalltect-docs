## Overview

The following examples demonstrate common ways to initialize a project.

Most users only need the default initialization, while advanced workflows can
use initialization modes and overwrite options to customize the generated
resources.

<InfoBox
    variant="tip"
    title="Getting Started"
>

If this is your first time using Custy, begin with the default initialization.

</InfoBox>

<InfoBox
    variant="tip"
    title="Safely Refresh the Example Catalog"
>

Run `custy init --mode examples` after upgrading Custy to add newly packaged
examples without replacing examples you already customized. Add `--force` only
when you intentionally want packaged content to replace existing example files.

</InfoBox>

---

<Section
    title="Typical First-Time Setup"
>

For a new project, the recommended workflow is:

1. Run `custy init`.
2. Review the generated configuration.
3. Customize templates if necessary.
4. Commit the generated resources to version control.

This allows every contributor to share the same project configuration from the
beginning.

</Section>

---

<InfoBox
    variant="note"
    title="Public Command"
>

Project initialization is exposed as `custy init`. The current public Run
argument does not accept an `init` profile.

</InfoBox>
