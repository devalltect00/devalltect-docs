## Overview

The `custy init` command is the public interface for project initialization.

<InfoBox
    variant="tip"
    title="Recommendation"
>

Initialize the project with:

`custy init`

The internal initialization profile is not exposed by the current public
`custy run` argument.

</InfoBox>

---

<Section
    title="Docker"
>

After building `custy-prod:latest` from Custy's production Docker target,
invoke the command against the intended mounted project.

<Terminal>

{`
docker run -it --rm \
    -v "<project>:/workspace" \
    -w /workspace \
    custy-prod:latest \
    init
`}

</Terminal>

See the [Docker setup guide](../../getting-started/docker) for the build command,
host requirements, workspace-mount behavior, and Git credential considerations.

</Section>

---

<InfoBox
    variant="note"
    title="Public Command"
>

Use `custy init`. `custy run init` is not accepted by the current public Run
profile argument.

</InfoBox>
