## Overview

Running `custy init` prepares a project by generating the resources that Custy
uses during future operations.

Rather than executing Git workflows immediately, the command creates a
customizable project workspace that future commands can reuse.

<InfoBox
    variant="tip"
    title="Safe Operation"
>

The initialization workflow does not create commits, tags, releases, or modify
your Git history.

Its only responsibility is preparing the project for future Custy operations.

</InfoBox>

---

<InfoBox
    variant="note"
    title="Designed for Reuse"
>

The generated configuration and templates become part of your project.

They can be edited, committed to version control, and shared with other
developers working on the same repository.

Running init again is additive for packaged examples by default: new nested
examples are copied while existing example files remain unchanged.

</InfoBox>
