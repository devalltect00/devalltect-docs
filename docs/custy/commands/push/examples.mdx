## Overview

These examples prioritize dry-run because several advertised destination
controls are not yet reliably propagated into the workflow engine.

<InfoBox
    variant="warning"
    title="Read every resolved destination"
>

Cancel normal execution when the reported main or backup remote is not the
intended destination.

</InfoBox>

    title="Common Examples"

<CommandExample
    examples={[
        {title: "Preview resolved destinations", command: "custy --dry-run push", description: "Run validation and inspect which main remotes the engine resolves.", notes: "Use this before every unfamiliar repository or configuration."},
        {title: "Preview HEAD and a release tag", command: "custy --dry-run push --tag v1.4.0", description: "Show the intended HEAD and tag operations for each resolved remote."},
        {title: "Synchronize an eligible backup", command: "custy push --sync-backup --tag v1.4.0", description: "Request backup synchronization in addition to normal main-remote processing.", notes: "Non-critical branch rules can skip backup synchronization."},
        {title: "Run only after review", command: "custy push --tag v1.4.0", description: "Push HEAD and the selected tag using the engine's actual resolved destinations."},
    ]}
/>

</Section>

<InfoBox
    variant="note"
    title="Examples reflect current behavior"
>

These examples intentionally avoid presenting `--remote`, `--all-remote`, or
`--skip-tag` as reliable until their adapter mapping is corrected.

</InfoBox>
