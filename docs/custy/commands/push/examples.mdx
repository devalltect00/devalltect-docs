## Overview

These examples use dry-run to verify the effective destination set before
performing remote mutations.

<InfoBox
    variant="warning"
    title="Read every resolved destination"
>

Cancel normal execution when the reported main or backup remote is not the
intended destination.

</InfoBox>

<Section
    title="Common Examples"
>

<CommandExample
  examples={[
    {
      title: "Preview resolved destinations",
      command: "custy --dry-run push",
      description: "Run validation and inspect which main remotes the engine resolves.",
      notes: "Use this before every unfamiliar repository or configuration.",
    },
    {
      title: "Push to exactly one remote",
      command: "custy push --remote upstream",
      description: "Override all configured groups and push only to upstream.",
    },
    {
      title: "Push all configured groups",
      command: "custy push --all-remote",
      description: "Push the de-duplicated main and eligible backup groups.",
    },
    {
      title: "Preview HEAD and a release tag",
      command: "custy --dry-run push --tag v1.4.0",
      description:
        "Show the intended HEAD and tag operations for each resolved remote.",
    },
    {
      title: "Synchronize an eligible backup",
      command: "custy push --sync-backup --tag v1.4.0",
      description:
        "Request backup synchronization in addition to normal main-remote processing.",
      notes: "Non-critical branch rules can skip backup synchronization.",
    },
    {
      title: "Run only after review",
      command: "custy push --tag v1.4.0",
      description:
        "Push HEAD and the selected tag using the engine's actual resolved destinations.",
    },
  ]}
/>

</Section>

---

<InfoBox
    variant="note"
    title="Skip a tag deliberately"
>

Use `custy push --skip-tag` to push HEAD without pushing a tag. In Release
and Full profiles, the same option also prevents tag creation.

</InfoBox>
