The following examples demonstrate common ways to validate a project before
executing Git or Custy workflows.

<InfoBox
    variant="tip"
    title="When Should I Run Validation Manually?"
>

Running **custy validate** is most useful when you want to inspect your
project's readiness before executing a larger workflow.

If you primarily use **custy run**, validation is already included as the first
workflow stage.

</InfoBox>

---

<Section
    title="Common Situations"
>

Manual validation is especially helpful when:

- Setting up a project for the first time.
- Reviewing changes before creating a commit.
- Confirming that required configuration files exist.
- Verifying template files after running `custy init`.
- Diagnosing workflow failures before retrying a release.

</Section>
