## Overview

After completing validation, Custy reports whether the project satisfies the
requirements needed for subsequent workflows.

Successful validation indicates that the checked prerequisites have been
verified successfully.

If validation encounters a problem, execution stops immediately and Custy
reports the reason together with guidance for resolving the issue.

<Section
    title="Successful Validation"
>

When every validation step succeeds:

- The repository satisfies the configured prerequisites.
- Required project resources are available.
- Workflow-oriented commands may safely continue.
- No repository history is modified.

Successful validation only confirms readiness.

It does not create commits, tags, releases, or modify your project.

</Section>

---

<Section
    title="Validation Failure"
>

When validation fails:

- The current validation step is reported.
- Remaining validation steps are skipped.
- A descriptive message explains the problem.
- A helpful hint is provided whenever possible.

This fail-fast behavior helps identify and resolve problems quickly before
attempting more complex workflow operations.

</Section>

---

<InfoBox
    variant="tip"
    title="Read the Hint"
>

Whenever validation fails, read the accompanying hint before retrying.

Most validation failures can be resolved by following the suggested action,
such as initializing a Git repository, generating required templates, or
staging project changes.

</InfoBox>

---

<Section
    title="Dry Run"
>

When validation is executed as part of a workflow using the global
<code>--dry-run</code> option, Custy reports what would normally happen without
performing workflow actions that modify the repository.

This allows you to inspect workflow readiness before executing the actual
operation.

</Section>
