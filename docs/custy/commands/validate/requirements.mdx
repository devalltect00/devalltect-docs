## Overview

Before running **custy validate**, your project should satisfy a few basic
requirements.

Most validation failures occur because one or more of these prerequisites are
missing rather than because of a problem with Custy itself.

<InfoBox
    variant="tip"
    title="Not Every Requirement Is Mandatory"
>

Some validation checks depend on your project configuration and workflow.

Commitizen is optional unless the commit validation provider or version
strategy explicitly requires it. Auto mode safely uses Custy's built-in
validator when Commitizen is not configured or installed.

</InfoBox>

<Section
    title="Recommended Preparation"
>

Before running validation, it is recommended that you:

- Open the project's root directory.
- Verify that Git has been initialized.
- Review your <code>.config/custy/config.toml</code> configuration.
- Stage changes if you intend to continue with a commit workflow.
- Confirm that required template files have been generated.

These steps reduce the likelihood of validation failures.

</Section>

---

<InfoBox
    variant="note"
    title="Automatic Validation"
>

If you normally execute workflows through <code>custy run</code>, you usually
do not need to run <code>custy validate</code> manually because validation is
performed automatically before the workflow continues.

</InfoBox>

---

<Section
    title="What Is Not Required?"
>

Validation does **not** require:

- Existing Git commits.
- Existing Git tags.
- A published release.
- A remote push.

The command verifies readiness for future operations rather than checking
project history.

</Section>
