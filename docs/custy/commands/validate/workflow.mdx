## Overview

Validation is the first stage of nearly every workflow-oriented operation in
Custy.

Its purpose is to verify that the project is ready before later stages perform
actions such as committing, tagging, pushing, or generating releases.

---

<InfoBox
    variant="tip"
    title="Automatic Workflow Stage"
>

When using commands such as `custy run`, validation is executed automatically
before the workflow continues.

Running `custy validate` allows you to execute only the validation stage.

</InfoBox>

<Section
    title="Workflow Stages"
>

<WorkflowStep
    title="1. Resolve Configuration"
>

Custy begins by loading the project's effective configuration.

Validation targets such as the configured remote, version file, and template
locations are resolved before any checks begin.

</WorkflowStep>

<WorkflowStep
    title="2. Validate the Repository"
>

Custy verifies that the current directory is a Git repository and confirms
that required Git remotes are available.

If either check fails, validation stops immediately.

</WorkflowStep>

<WorkflowStep
    title="3. Validate Project Resources"
>

Custy verifies the resources required by later workflow stages.

Typical resources include:

- Version files
- Commit message templates
- Tag message templates

</WorkflowStep>

<WorkflowStep
    title="4. Validate Repository State"
>

Before commit-oriented workflows continue, Custy confirms that the repository
is in an acceptable state.

Depending on the selected options, this may include checking staged changes or
performing automatic staging.

</WorkflowStep>

<WorkflowStep
    title="5. Complete Validation"
>

If every validation step succeeds, Custy reports a successful validation
result.

Workflow-oriented commands may then continue with the next stage, such as
committing, tagging, or pushing changes.

</WorkflowStep>

</Section>

---

<InfoBox
    variant="note"
    title="Fail-Fast Workflow"
>

Validation follows a fail-fast approach.

If any validation step fails, the remaining checks are skipped and the
workflow stops immediately.

This prevents later workflow stages from operating on an invalid project
state.

</InfoBox>

---

<Section
    title="Validation in Larger Workflows"
>

Validation is designed to be reusable.

It can be executed directly using:

- `custy validate`

or automatically as part of workflow commands such as:

- `custy run commit`
- `custy run tag`
- `custy run push`
- `custy run release`

Using the shared validation stage ensures that every workflow begins with the
same set of readiness checks.

</Section>
