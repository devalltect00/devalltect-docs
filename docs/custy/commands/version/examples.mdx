## Overview

The following examples demonstrate common ways to synchronize version
information across supported project files.

Each example focuses on a single concept so that individual options can be
combined as needed.

---

<Section
    title="Basic Examples"
>

<CommandExample
  examples={[
    {
      title: "Synchronize Project Version",
      description: "Update project version files using the configured defaults.",
      command: `custy version update`,
      result:
        "Custy generates the next version and synchronizes every supported project version file.",
    },
  ]}
/>

</Section>

---

<Section
    title="Selecting a Version Strategy"
>

<CommandExample
  examples={[
    {
      title: "Use Semantic Versioning",
      description: "Generate the next version using the SemVer strategy.",
      command: `custy version update --strategy semver`,
      result: "The next version is calculated according to Semantic Versioning.",
    },
    {
      title: "Use PEP 440",
      description: "Generate the next version using the Python PEP 440 strategy.",
      command: `custy version update --strategy pep440`,
      result:
        "Custy generates a PEP 440 compliant version before synchronizing project files.",
    },
  ]}
/>

</Section>

---

<Section
    title="Version Generation"
>

<CommandExample
  examples={[
    {
      title: "Minor Release",
      description: "Generate the next minor version.",
      command: `custy version update --bump minor`,
      result:
        "The generated version increments the minor component according to the selected strategy.",
    },
    {
      title: "Explicit Version",
      description: "Synchronize project files using a specific version.",
      command: `custy version update --tag v2.5.0`,
      result: "The supplied version is synchronized without generating a new one.",
    },
  ]}
/>

</Section>

<InfoBox
    variant="tip"
    title="One Strategy per Execution"
>

Although Custy supports multiple versioning strategies, a single Version
Update execution uses only one strategy to determine the version before
synchronizing project files.

</InfoBox>
