## Overview

The step-name mismatch is an application blocker, not a project-configuration
problem. Correct and validate the implementation before diagnosing later
transition behavior.

<InfoBox
    variant="danger"
    title="Do not work around the source mismatch in configuration"
>

The command requests `finalize` while registration exposes `finalize_step`.

</InfoBox>

---

## An Unknown `finalize` Step Is Reported

<Section compact>

This is the known source mismatch. It requires an application fix, not a
configuration change.

</Section>

---

## `--check-transition` Is Rejected

<Section compact>

Use the currently declared `--check_transition` spelling or its `-ct` short
form.

</Section>

---

## A Tag Override Is Rejected

<Section compact>

Use the current shared explicit-tag shape: `vX.Y.Z`. The validator normalizes a
missing `v`, but it does not accept broader generated prerelease or PEP 440
forms on this option.

</Section>

---

## Enforcement Behavior Is Unclear

<Section compact>

Do not enable enforcement. Review `[tool.custy.cli.workflow]`, test validation
in a disposable repository after the implementation is fixed, and document the
team's allowed transitions first.

</Section>

---

## Backup Synchronization Is Skipped

<Section compact>

Inspect configuration, branch eligibility, remotes, and dry-run diagnostics.
Do not assume a backup occurred without a clear success result.

</Section>
