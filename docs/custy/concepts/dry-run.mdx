## Overview

Dry-run mode lets Custy resolve a command and report supported operations
without performing their normal mutations. It is the recommended first step
for commands and profiles that can edit project files, stage changes, create
Git history, or push to remotes.

<InfoBox
    variant="info"
    title="Place the option before the command"
>

`--dry-run` is a global Custy option. Use `custy --dry-run run release`, not
`custy run release --dry-run`.

</InfoBox>

<Section title="How the Effective Mode Is Resolved">

Custy resolves dry-run behavior in this order: an explicit CLI option, the
`tool.custy.cli.execution.dry_run` project setting, and finally the built-in
default of `false`. This means omitting `--dry-run` does not necessarily enable
normal execution when the project configuration already sets `dry_run = true`.

<Terminal title="Choose preview or normal execution explicitly" language="bash">

{`# Force preview mode, regardless of the configured default
custy --dry-run changelog generate

# Force normal execution, even when dry_run = true in configuration

custy --no-dry-run changelog generate`}

</Terminal>

</Section>

<InfoBox
    variant="danger"
    title="Dry run is a simulation, not a guarantee"
>

Dry-run mode is designed to suppress mutations in supported stages. It can
still fail while reading or resolving state, and a successful preview does not
guarantee that a later normal run will see identical files, Git state,
credentials, remotes, or network conditions.

</InfoBox>

<InfoBox
    variant="info"
    title="Diagnostic logging remains active"
>

Dry-run protects the command's intended project, Git, and remote mutations.
Custy's normal logging setup can still create or append diagnostic log files.

</InfoBox>

---

<Section
    title="After the Preview"
>

Before normal execution:

- confirm the selected command or profile is the smallest one that reaches the
  intended result;
- review paths, generated content, commit and tag messages, and every remote;
- make sure the working tree contains only changes you intend Custy to include;
- keep recovery information or backups when the operation can rewrite files or
  create history; and
- inspect the working tree, commit, tags, and remotes again after execution.

</Section>
