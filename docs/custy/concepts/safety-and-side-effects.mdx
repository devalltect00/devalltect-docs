## Overview

Custy ranges from inspection and validation to project-file generation, Git
history creation, and remote publication. Safety begins by choosing the
smallest suitable command, understanding its complete effect set, previewing
supported mutations, and verifying state after execution.

<InfoBox variant="info" title="Dry-run separates discovery from mutation">

During dry-run, Custy may still read configuration and project files, inspect
repository history, branches, tags, and remotes, validate inputs, and render
previews. Intended file changes, editor launches, Git mutations, and remote
mutations are simulated. Diagnostic logging can still write to Custy's log
destination.

</InfoBox>

<InfoBox
    variant="info"
    title="Profiles inherit every included effect"
>

A pipeline profile can include many direct-operation behaviors. When multiple
public profiles are combined, treat their requirements and side effects as a
union even though overlapping steps are deduplicated.

</InfoBox>

<InfoBox
    variant="danger"
    title="Remote effects deserve separate review"
>

Local recovery does not automatically undo a remote push. When an operation
can publish changes, verify the remote name, URL, branch, tag, credentials, and
multi-remote behavior before normal execution.

</InfoBox>
