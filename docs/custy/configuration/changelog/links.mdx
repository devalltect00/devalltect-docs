## Properties

<Terminal title="Safe generated default" language="toml">

{`[tool.custy.changelog.links]
repository = ""
enable_compare = false`}

</Terminal>

To enable links, replace the empty value with the real project repository URL:

<Terminal title="Enable comparison links" language="toml">

{`[tool.custy.changelog.links]
repository = "https://github.com/your-org/your-project"
enable_compare = true`}

</Terminal>

<InfoBox variant="warning" title="Placeholder and invalid URLs are not used">

If comparison is enabled while `repository` is empty, still contains an
example such as `org/project`, or is not a valid HTTP(S) browser URL, Custy
logs a warning and continues generating the changelog without comparison
links. The changelog command does not fail for this recoverable setting.

</InfoBox>

<InfoBox variant="note" title="Two switches affect visibility">

`enable_compare` creates comparison URLs. `render.show_compare_link` decides
whether the Jinja template displays available URLs.

</InfoBox>

## Repository URL vs Git remotes

| Setting                                   | Value                                                 | Purpose                                               |
| ----------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------- |
| `changelog.links.repository`              | Browser URL, such as `https://github.com/org/project` | Build links in `CHANGELOG.md`                         |
| `git.default_remote`                      | One remote name, such as `origin`                     | Provide a fallback for operations that use one remote |
| `git.main_remotes` / `git.backup_remotes` | Lists of remote names                                 | Group authoritative and mirror destinations           |

Use `git remote -v` to discover remote names and URLs. Do not copy a remote
name such as `origin` into `changelog.links.repository`.
