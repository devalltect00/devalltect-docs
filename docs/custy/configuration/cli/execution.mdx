<Section title="Dry-Run Resolution">

Custy resolves `dry_run` using CLI → configuration → built-in default
precedence. An explicit global option therefore overrides this setting.

<Terminal title="Override the configured default" language="bash">

{`# Enable simulation
custy --dry-run run release

# Disable simulation and use normal execution
custy --no-dry-run run release`}

</Terminal>

Read-only discovery and validation may still execute in preview mode. Normal
diagnostic logging also remains active and may update the configured log file.

</Section>

<InfoBox variant="danger" title="Force and automatic staging broaden side effects">

Keep force settings disabled in shared configuration. Pairing `auto_stage = true`
with `stage_mode = "all"` can include tracked and untracked changes.

</InfoBox>

<InfoBox variant="note" title="Use the provider table for new projects">

Configure [`tool.custy.commit.validation`](../commit-validation) for automatic
discovery and explicit fallback behavior. Keep `check_cz` only when an older
configuration or CLI workflow needs the strict boolean override.

</InfoBox>

<InfoBox variant="warning" title="Use the CLI for skip-check behavior">

Until `skip_checks` and `skip_check` are aligned in the source and generated
template, use the explicit command option and verify the displayed plan.

</InfoBox>
