<InfoBox variant="info" title="A configuration file alone does not install a hook">

In `auto` mode, `.pre-commit-config.yaml` without an installed
`.git/hooks/pre-commit` wrapper behaves like a normal no-hook repository. Use
`pre-commit install` when the project intends Git to enforce those checks, or
choose `pre_commit` explicitly when Custy should require direct execution.

</InfoBox>

<InfoBox variant="warning" title="Direct execution is validation, not a bypass">

Custy uses Git's `--no-verify` only after every recognized wrapper that flag
would bypass has completed successfully through `pre-commit`. Unknown custom
hooks, unavailable tooling, missing configuration, and failed checks stop the
workflow. There is no `skip` mode.

</InfoBox>

<Section title="Local and Docker Guidance">

- Keep `mode = "auto"` for most projects, including projects that do not use
  pre-commit.
- Use `native` when custom hooks are already portable across every execution
  environment.
- Use `pre_commit` when project policy requires direct framework execution.
- Install local support with `pip install "custy[hooks]"`. The production
  image already contains `pre-commit`.
- A failing direct check returns `PRE_COMMIT_HOOK_FAILED` and does not create a
  Git commit.

</Section>
