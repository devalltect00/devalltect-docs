## Goal

Use an isolated environment whose `custy` executable points to the working
source checkout. Editable installation means a Python source edit is available
to the next invocation without rebuilding or reinstalling the package.

<Section title="Manual Setup">

<Terminal title="Create and install" language="bash">

{`python -m venv venv

# Windows PowerShell

venv\\Scripts\\Activate.ps1

# Linux or macOS

# source venv/bin/activate

python -m pip install --upgrade pip
python -m pip install -e ".[dev]"`}

</Terminal>

The `dev` dependency group installs pytest and coverage, Ruff, Black, build and
publishing tools, pre-commit, and Commitizen. Add `docs` only when working with
the Custy repository's legacy MkDocs source: `python -m pip install -e
".[dev,docs]"`.

</Section>

---

<Section title="Makefile Setup">

The repository Makefile expects a `venv/` environment and invokes its Python
and pip executables directly.

<Terminal title="Equivalent setup helpers" language="bash">

{`make venv
make upgrade-pip
make install-dev

# Or run the combined setup, including docs and pre-commit

make setup`}

</Terminal>

Run `make help-local` to review the active local helper groups before using
less familiar targets.

</Section>

---

<Section title="Pre-Commit Workflow">

The Make helpers invoke pre-commit through the repository's `venv/` Python
interpreter. Install the Git hook once, validate its configuration after an
edit, and choose either staged-file or all-file checks for daily work.

<Terminal title="Pre-commit setup and checks" language="bash">

{`# Install the Git hook and its isolated hook environments
make pre-commit-install-hooks

# Validate .pre-commit-config.yaml

make pre-commit-validate

# Check files currently staged for commit

make pre-commit-run-staged

# Check every tracked repository file

make pre-commit-run`}

</Terminal>

<InfoBox variant="warning" title="Reserve refresh for intentional hook upgrades">

`make pre-commit-refresh` runs `autoupdate`, clears cached hook environments,
reinstalls the hook environments, and runs every hook against all files. It can
change `.pre-commit-config.yaml` and active source files, and may require
network access. Review and validate the resulting diff before keeping it.

</InfoBox>

</Section>

<InfoBox variant="warning" title="Use the environment executable in automation">

Activating a virtual environment is convenient for an interactive shell, but
scripts and diagnostics are more predictable when they invoke the selected
environment's Python directly, such as `venv\Scripts\python.exe` on Windows.

</InfoBox>
