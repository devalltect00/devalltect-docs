## Overview

The public Dev profile coordinates routine development work. Its current
registered sequence validates and opens only the commit message, backs it up,
stages selected changes, creates a commit, and pushes branch `HEAD`.

For a first run, use global dry-run mode. Move to normal execution only when
the repository, generated resources, commit message, and remote destination
have all been reviewed.

<InfoBox
    variant="warning"
    title="Dev ends with a push"
>

`custy run dev` is not a local-only demonstration. Without `--dry-run`, the
registered profile reaches commit and push stages. Use `custy run commit` when
you need the documented local commit profile instead.

</InfoBox>

<InfoBox
    variant="note"
    title="Current profile boundary"
>

The registered Dev profile does not prepare or apply a version, initialize a
release workflow, generate release artifacts or a changelog, open a tag
message, create a tag, or push a tag.

</InfoBox>

</Section>

<Section
    title="Preview the Workflow"
>

Global options belong before `run`.

<Terminal title="Dry-run the Dev profile" language="bash">

{`custy --dry-run run dev`}

</Terminal>

Review the output for the resolved commit-message file, backup locations,
staging behavior, commit preparation, and remote destination. If any part is
unexpected, stop and adjust the project configuration or command options.

</Section>

---

<Section
    title="Run Normally When Ready"
>

Normal execution is an explicit decision after the preview and repository
review.

<Terminal title="Run the development profile" language="bash">

{`custy run dev`}

</Terminal>

After completion, verify both local and remote state.

<Terminal title="Post-run verification" language="bash">

{`git status --short --branch
git log -1 --decorate --oneline
git remote -v`}

</Terminal>

<InfoBox
    variant="warning"
    title="Remote selection is configuration-driven"
>

The Dev profile honors explicit `--remote`, `--all-remote`, and the
configured Git remote groups. Confirm the effective destinations during dry-run
and review the dedicated Push documentation before normal execution.

</InfoBox>

</Section>
