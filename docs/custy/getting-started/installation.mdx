## Overview

Custy can be installed from a source checkout, a Python artifact attached to a
release, or the Git repository itself. Contributors should use an editable
installation with the development dependency group. Docker is a separate
alternative when you do not want to install Python or Git directly on the host.

<InfoBox
    variant="info"
    title="No public package-index assumption"
>

These instructions do not assume that `pip install custy` resolves to this
project on a public package index. Install a reviewed source checkout, release
artifact, or Git revision explicitly.

</InfoBox>

<Section
    title="Method 1: Install from a Source Checkout"
>

Clone the repository, create a virtual environment, and install the runtime
package. This is the recommended native path when no reviewed release artifact
has been selected.

<Terminal title="Clone and create the environment" language="bash">

{`git clone https://github.com/devalltect00/Custy.git
cd Custy
python -m venv venv`}

</Terminal>

Activate the environment for your shell.

<Terminal title="Windows PowerShell" language="powershell">

{`venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
python -m pip install .`}

</Terminal>

<Terminal title="Linux or macOS" language="bash">

{`source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .`}

</Terminal>

</Section>

---

<Section
    title="Method 2: Install a Release Artifact"
>

Custy's release workflow is configured to attach a Python wheel and source
distribution. Open the
[Custy Releases page](https://github.com/devalltect00/Custy/releases), choose a
reviewed release, and confirm that the selected release actually contains the
artifact before downloading it.

<Terminal title="Install a downloaded wheel" language="bash">

{`python -m pip install ./custy-<version>-py3-none-any.whl`}

</Terminal>

<Terminal title="Install a downloaded source distribution" language="bash">

{`python -m pip install ./custy-<version>.tar.gz`}

</Terminal>

<InfoBox
    variant="warning"
    title="Do not pin documentation to one old release"
>

Artifact availability and version numbers change over time. Use the general
Releases page, select the intended version deliberately, and verify the asset
name shown by that release.

</InfoBox>

</Section>

---

<Section
    title="Method 3: Install Directly from Git"
>

When you do not need a local checkout, pip can install a reviewed Git tag or
commit into the active environment.

<Terminal title="Install a reviewed revision" language="bash">

{`# Replace <tag-or-commit> with the exact revision you reviewed
python -m pip install "git+https://github.com/devalltect00/Custy.git@<tag-or-commit>"`}

</Terminal>

Omitting `@<tag-or-commit>` follows the repository's default branch and is less
reproducible.

</Section>

<Section
    title="Editable Developer Installation"
>

Contributors working on Custy itself should install the source tree in editable
mode with the development dependencies declared in `pyproject.toml`.

<Terminal title="Editable install with development tools" language="bash">

{`python -m pip install -e ".[dev]"`}

</Terminal>

Use `python -m pip install -e .` only when you need editable runtime code
without the optional development tools. Add `docs` when working on Custy's
legacy MkDocs sources: `python -m pip install -e ".[dev,docs]"`.

<InfoBox
    variant="tip"
    title="Why use python -m pip?"
>

Calling pip through `python -m pip` ensures that installation uses the Python
interpreter from the active virtual environment.

</InfoBox>

</Section>

---

<Section
    title="Optional Makefile Helpers"
>

The repository Makefile can create the standard `venv/` environment and run
the editable installation targets. These helpers are intended for a Custy
source checkout and require GNU Make.

<Terminal title="Contributor setup with Make" language="bash">

{`make venv
make upgrade-pip
make install-dev`}

</Terminal>

- `make install` installs editable runtime dependencies.
- `make install-dev` adds the development dependency group.
- `make install-all` adds both development and legacy documentation tools.
- Make is only a convenience layer; the equivalent `python -m pip` commands
  remain valid without it.

</Section>

<Section
    title="Common Installation Problems"
>

<InfoBox
    variant="warning"
    title="Python version is too old"
>

If pip reports an incompatible Python version, install Python 3.14 or newer,
recreate the virtual environment with that interpreter, and install again.

</InfoBox>

<InfoBox
    variant="warning"
    title="custy is not recognized"
>

Confirm that the intended virtual environment is active. You can also invoke
its executable directly, such as `venv\Scripts\custy.exe --help` on Windows,
or use `python -m app --help` from the source checkout.

</InfoBox>

<InfoBox
    variant="warning"
    title="Git command is unavailable"
>

Install Git and make sure `git --version` works in the same shell. A successful
Python package installation alone does not provide the Git executable required
by Custy's main workflows.

</InfoBox>

</Section>
