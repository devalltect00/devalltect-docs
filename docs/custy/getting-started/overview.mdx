## Overview

This guide takes you from installation to a reviewed pipeline preview. You will
install Custy, generate project-specific resources, validate the repository,
and inspect a development pipeline before allowing it to change files or Git
history.

<InfoBox
    variant="info"
    title="Custy works with an existing project"
>

Custy is a workflow and release-automation CLI. It does not create your
application or initialize its Git history. Start from the root of the existing
repository that you want Custy to manage.

</InfoBox>

<Section
    title="The Short Version"
>

<Terminal title="Safe onboarding sequence" language="bash">

{`# From the root of an existing Git repository
custy --version
custy init
git status --short
custy validate
custy --dry-run run dev`}

</Terminal>

The dry run is the end of the basic onboarding sequence. Continue to normal
execution only after you understand the selected profile's file, Git, and
remote side effects.

</Section>

---

<InfoBox
    variant="warning"
    title="Pipeline commands can be consequential"
>

Profiles such as `dev`, `release`, and `full` can edit files, create Git
history, create tags, and push to remotes. Read the relevant profile page and
confirm repository state before running without `--dry-run`.

</InfoBox>
