## Overview

Dev is a deliberate daily-development profile. It prepares and reviews release
artifacts, generates the changelog, creates a commit, and pushes it. It does not
apply the prepared version and does not create a tag.

<Terminal title="Preview before normal execution" language="bash">

{`custy --dry-run run dev
custy run dev`}

</Terminal>

<InfoBox variant="info" title="Prepared version is not applied">

Dev includes version preparation because later services need version context,
but it does not include `apply_version_step`. It also omits `tag_step`. Use
Release when you need to write the new version and create a release tag.

</InfoBox>

<InfoBox variant="warning" title="Dev has a narrower validation prefix">

The profile explicitly begins with repository validation, not the full
pre-commit and pre-push validation subprofiles used by Release. Downstream
services can still reject invalid state. Confirm message files, staged changes,
and remotes before normal execution.

</InfoBox>

<Section title="Failure and Retry">

If Dev fails before commit, inspect generated files, edits, backups, and the Git
index. If it fails during or after push, verify whether the local commit and any
remote updates already completed. Do not rerun the whole profile until that
state is understood.

</Section>
