## Overview

Full uses the complete Release step list and adds `finalize_step` at the end.
Finalization can perform branch transitions, merges, pushes, or cleanup according
to the workflow case discovered earlier in the pipeline.

<Terminal title="Preview with extra care" language="bash">

{`custy --dry-run run full
custy run full`}

</Terminal>

---

<InfoBox variant="danger" title="Finalization runs after remote publication">

The release commit, tag, and push can succeed before finalization fails. Never
retry Full automatically. First inspect the local branches, commit, tag, every
remote, and the workflow transition that was attempted.

</InfoBox>

<InfoBox variant="warning" title="Finalization is conditional and experimental">

The engine skips post-workflow behavior when checks are skipped or no workflow
context is available. Some workflow cases only report information; others can
checkout, rebase or merge branches, push, or clean a release branch. If actions
run successfully, Custy can pause for confirmation before returning.

</InfoBox>

<Section title="Prefer Release by Default">

Choose `custy run release` when you need a complete tagged publication but do
not need branch lifecycle finalization. It has the same release stages and a
clearer completion boundary: push.
