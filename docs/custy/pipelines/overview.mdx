## Overview

A Custy pipeline is an ordered collection of registered steps. A public profile
such as `dev` or `release` selects a prepared collection; Custy resolves it,
builds each step, and executes the result one step at a time.

This section explains the system behind the command. Use the
[Run command guide](../commands/run/overview) when you need syntax, options,
examples, and troubleshooting for the CLI itself.

<InfoBox variant="tip" title="Choose the path that matches your goal">

If you only want to run Custy, start with [Profiles](./profiles). If you are
reviewing behavior, read [Execution Model](./execution-model). If you plan to
contribute code, continue to [Step System](./step-system).

</InfoBox>

<Section title="Public Boundary">

The current typed `custy run` argument accepts only `commit`, `tag`, `push`,
`dev`, `release`, and `full`. Internal resolver profiles are used by Custy's
implementation and direct commands, but they are not additional public Run
names.

<Terminal title="Public profile examples" language="bash">

{`# Preview a daily development pipeline
custy --dry-run run dev

# Run a complete release pipeline
custy run release

# Merge two supported profiles
custy --dry-run run commit push`}

</Terminal>

</Section>

---

<Section title="Important Safety Boundary">

Pipeline execution is sequential, not transactional. If a step fails, Custy
stops and reports the failed step, but it does not automatically undo changes
made by earlier steps. Always inspect files, Git history, tags, and remote state
before retrying.

</Section>
