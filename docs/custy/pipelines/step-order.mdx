## Overview

`STEP_ORDER` is a global sort-key map used when Custy merges two or more
profiles. Lower values are placed earlier. The gaps between phases leave room
for future steps without renumbering the entire pipeline.

<InfoBox variant="info" title="Priority is ordering, not concurrency">

These values do not control threads, operating-system priority, timing, or
parallel execution. Custy still executes one step at a time. The number only
determines position while normalizing a merged profile.

</InfoBox>

<Section title="Worked Example: push + commit">

Both `custy run push commit` and `custy run commit push` currently normalize to
the same 19 steps. The CLI input order does not move `push_step` ahead of
validation, preparation, or `commit_step`.

---

<InfoBox variant="warning" title="STEP_ORDER is a safety-sensitive contract">

Changing a priority can move validation after file writes, or change whether
commit, tag, push, cleanup, and finalization occur in the intended sequence.
Contributors should update resolver tests, profile tests, integration tests, and
this reference whenever ordering changes.

</InfoBox>
