## Current baseline

These pages describe **Custy v2.0.0** and were last reviewed against the active
source on **August 22, 2026**. The date records a deliberate documentation
review; it is not an automatic Git edit date or deployment timestamp.

<InfoBox variant="info" title="Remote tags are checked at build time">

The portal runs `git ls-remote --tags --refs` when Docusaurus starts or builds.
It does not query GitHub from each visitor's browser. The deployed result stays
unchanged until the documentation site is built again.

</InfoBox>

Custy currently uses automatic PEP 440 detection while its existing repository
tags are being migrated. Change `tagFormat` to `semver` after the repository tag
strategy changes to SemVer.

[`v2.0.0` source snapshot](https://github.com/devalltect00/Custy/tree/v2.0.0)

<Section title="Configuration Reference">

configure the documentation portal itself; they are not Custy CLI settings and
do not belong in `.config/custy/config.toml`.

### Automatic mode

```ts title="src/data/projects.ts"
documentation: {
  version: "2.0.0",
  versionTag: "v2.0.0",
  lastReviewed: "2026-08-22",
  releaseUrl: "https://github.com/devalltect00/Custy/releases/tag/v2.0.0",
  statusPath: "/docs/custy/reference/documentation-status",
  freshness: {
    mode: "auto",
    repositoryUrl: "https://github.com/devalltect00/Custy.git",
    tagFormat: "pep440",
    releasesUrl: "https://github.com/devalltect00/Custy/releases",
    includePrereleases: false,
    timeoutMs: 10_000,
    fallbackStatus: "unknown",
  },
}
```

### Manual mode

Use manual mode for custom version formats, repositories that cannot be reached
from the build environment, or projects whose release status requires human
judgment.

```ts title="src/data/projects.ts"
freshness: {
  mode: "manual",
  status: "current", // current | outdated | preview
  latestVersionTag: "custom-release-42", // optional
}
```

<Section title="Tag Selection Rules">

1. Query direct remote tag refs without cloning the repository.
2. Remove `refs/tags/`, discard peeled `^{}` duplicates defensively, and
   preserve the original tag for display.
3. Accept the conventional optional `v` prefix.
4. Ignore tags that do not match the configured `semver` or `pep440` grammar.
5. Exclude prereleases unless `includePrereleases` is `true`.
6. Sort compatible tags with the selected grammar rather than lexical text
   order. For example, `1.10.14` correctly sorts after `1.10.9`.
7. Compare the normalized latest version to the documented baseline.

Custom tag grammars are not accepted in automatic mode. Select manual mode
instead of approximating a custom ordering rule.

</Section>

<Section title="Failure Handling">

- Invalid maintainer configuration, including an unsupported format, invalid
  baseline, missing remote URL, or timeout outside the supported range, stops
  the build with an actionable error.
- Missing Git, network failures, authentication failures, and timeouts do not
  silently claim that documentation is current. The plugin uses
  `fallbackStatus` and prints a build warning.
- A successful query with no compatible tags produces the same fallback
  behavior with the diagnostic code `no-compatible-tags`.
- Remote error details remain in build logs; raw process errors are not exposed
  to documentation visitors.
- The remote query runs once per configured project per Docusaurus process, not
  once per page.

For private repositories, ensure the build environment can authenticate the
configured Git URL. Do not place credentials or tokens directly in
`src/data/projects.ts`.

</Section>

<Section title="Deployment and Release Automation">

Automatic detection is evaluated when `yarn start`, `yarn build`, or another
Docusaurus command loads the plugin. A new Custy tag does not change an already
deployed static site until Devalltect Docs is rebuilt.

The current Pages workflow rebuilds on pushes to the documentation repository
and manual workflow runs. A later integration can trigger a documentation build
from a Custy release through `repository_dispatch`, or a scheduled workflow can
periodically recheck tags. Those workflow triggers are independent of the
freshness resolver.

</Section>

<Section title="Documentation Maintenance">

Maintainers should update the central baseline when a Custy release changes
documented commands, options, configuration, workflows, output, architecture,
or other user-visible behavior. A complete synchronization should include:

1. Review the new release tag and active source behavior.
2. Update affected English pages.
3. Apply the same technical changes to the Indonesian pages while preserving
   command names, options, paths, configuration keys, and code exactly.
4. Change the baseline version, tag, release URL, and last-reviewed date.
5. Confirm `tagFormat` still matches the repository strategy. For Custy, change
   `pep440` to `semver` after the planned tag migration.
6. Run the freshness tests, type checking, and production builds for both
   locales.

The global notice reads one central metadata entry and the build-time resolver
result. It remains hidden when documentation is current and appears only when
readers need preview, outdated, or verification-failure context.

</Section>
