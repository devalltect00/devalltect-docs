<Section title="Working Directory">

Run Custy from the project root that contains `.config/custy/config.toml`, the
configured project source, and the target Git repository. Relative
configuration, template, backup, log, version, and changelog paths are resolved
from the process working directory.

<Terminal title="Verify the intended environment" language="bash">

{`custy --version
custy --no-banner validate
git status`}

</Terminal>

</Section>

<Section title="External Tools and Credentials">

- Custy invokes `git` and relies on the normal Git executable lookup.
- Remote authentication belongs to Git and the configured credential helper,
  SSH agent, CI secret setup, or container environment. Custy does not read a
  dedicated GitHub or GitLab token variable in the active core path.
- The editor launcher does not currently read `EDITOR` or `VISUAL`; it tries
  `code --wait` and then `notepad`.
- Commitizen strategy behavior invokes `cz` as an external subprocess.
- Docker bind mounts determine which host project appears as the container's
  working directory.

</Section>

---

<InfoBox variant="warning" title="Legacy Windows redirected output can fail on Unicode">

During source verification, Rich help redirected through a legacy Windows
`cp1252` stream raised `UnicodeEncodeError` while rendering emoji. Use a modern
UTF-8 terminal and configure automation capture for UTF-8. This limitation
affects presentation and can prevent help output from completing.

</InfoBox>
