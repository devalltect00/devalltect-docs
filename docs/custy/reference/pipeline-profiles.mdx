<InfoBox variant="danger" title="Resolver name does not mean public Run value">

For example, `validate` is a real profile used by `custy validate`, but the
typed Run argument does not accept `custy run validate`.

</InfoBox>

<Section title="Resolution and Ordering Rules">

- Resolving one profile preserves its declared expanded order.
- Resolving multiple profiles expands nested definitions, removes duplicate
  step names, and performs a stable sort by `STEP_ORDER` priority.
- A missing priority receives fallback value `999` and therefore moves behind
  explicitly prioritized built-in steps.
- Cyclic nested profiles and unknown names fail resolution.
- Duplicate public arguments are rejected by the CLI validator.
- Execution stops on the first failing step and does not roll back earlier
  successful side effects.

</Section>

---

<InfoBox variant="warning" title="Full includes experimental finalization">

The `full` value is accepted publicly, but its additional finalization step
uses evolving workflow behavior. Prefer `release` unless that final phase is
specifically required and has been reviewed in a disposable environment.

</InfoBox>
