<Section title="Basic SemVer and PEP 440 Bridge">

<Terminal title="Supported conversion examples" language="text">

{`PEP 440              SemVer-style
1.2.3a1       <->      v1.2.3-alpha.1
1.2.3b2       <->      v1.2.3-beta.2
1.2.3rc1      <->      v1.2.3-rc.1
1.2.3.dev1    <->      v1.2.3-dev.1
1.2.3.post1   <->      v1.2.3-post.1
1.2.3+linux   <->      v1.2.3+linux`}

</Terminal>

`VersionBridge` performs basic conversion for compatible three-part versions.
It returns no value for an invalid base and is not a complete implementation of
every SemVer or PEP 440 edge case. Review conversions involving epochs,
compound suffixes, or unusual local identifiers before writing project files.

</Section>

---

<InfoBox variant="warning" title="Explicit CLI tags are narrower than generated formats">

The shared explicit-tag validator normalizes a missing `v` prefix and accepts
only `vX.Y.Z`. Generated strategies support broader prerelease and PEP 440
forms, but passing those broader forms through an option wired to the shared
validator can fail during CLI parsing.

</InfoBox>

<InfoBox variant="warning" title="Current Commitizen implementation limitation">

Commitizen is an accepted strategy value, but the active delegation currently
passes an unsupported keyword to `SemverStrategy`. Treat this path as a known
implementation limitation until the source is corrected and validated.

</InfoBox>

---

<Section title="Generation, Conversion, and Sorting Are Separate">

- A `TagStrategy` generates the next value.
- `VersionBridge` converts compatible representations for project files.
- A `TagSorter` orders tags already present in Git.
- Commitizen generation produces SemVer-oriented output and therefore does not
  have a separate existing-tag sorter.
- Supplying an explicit accepted tag bypasses automatic generation.

</Section>
