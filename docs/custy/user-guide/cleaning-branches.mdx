## Goal

Use branch cleanup for deliberate repository maintenance after merged or stale
work is no longer needed. The active CLI subcommand is plural:
`custy cleanup branches`.

<InfoBox variant="danger" title="Matching branches can be deleted locally and remotely">

The active cleanup request defaults to local deletion and remote deletion at
`origin`. The public command does not currently expose switches for changing
those deletion flags or the remote. Treat every normal run as capable of
removing both copies.

</InfoBox>

<Terminal title="Narrow merged-branch cleanup" language="bash">

{`git fetch --all --prune
git branch --all

custy --dry-run cleanup brancheses \
 --prefix feature/ \
 --merge-status merged \
 --max-age 30d`}

</Terminal>

On PowerShell, place the command on one line or use PowerShell's continuation
syntax instead of the Bash backslashes shown above.

</Section>

---

<InfoBox variant="tip" title="Empty prefixes are a safe no-op">

When no prefixes resolve from either CLI or project configuration, no branches
are eligible. Add narrow prefixes deliberately; do not use broad prefixes merely
to make the command select something.

</InfoBox>

<Section title="If the Wrong Branch Was Deleted">

Stop additional cleanup. If you know the branch's last commit SHA and the
object is still available locally, recreate a local branch with standard Git
recovery tools, review it, and push only if the remote branch also needs to be
restored. If the commit is not known, inspect reflog and repository-host history
before taking further action.

This recovery is intentionally manual because Custy does not maintain a branch
deletion undo journal.

</Section>
