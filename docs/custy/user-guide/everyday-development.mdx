## Goal

Use the Dev profile when reviewed daily work should generate supporting
artifacts and changelog content, create one local commit, and finish with a
remote push. Choose a direct command instead when you need only one outcome.

<InfoBox variant="warning" title="Dev is not local-only">

Normal execution ends with `push_step`. Confirm the destination during dry-run
and review the [Push documentation](../commands/push/overview) before using Dev
on a repository whose remotes you have not verified.

</InfoBox>

<Section title="Verify Completion">

<Terminal title="Local verification" language="bash">

{`git status --short --branch
git log -1 --decorate --stat
git tag --points-at HEAD
git remote -v`}

</Terminal>

Expect the intended commit to exist and the working tree to reflect only any
deliberately uncommitted work. Dev should not create a new release tag. Confirm
the remote result using your repository host or an appropriate Git fetch and
comparison workflow.

</Section>

---

<InfoBox variant="danger" title="Do not blindly rerun a failed Dev profile">

Generated files, backups, the Git index, a commit, or a remote push may already
exist. Use [Troubleshooting Workflows](./troubleshooting-workflows) to identify
the last completed boundary first.

</InfoBox>
