## Overview

This guide organizes Custy around real tasks rather than individual command
options. Each journey explains what to prepare, which command or profile to
choose, what can change, how to verify success, and what to inspect when a run
stops partway through.

Use the [Command Reference](../commands/overview) when you need every option.
Use [Configuration](../configuration/overview) for persistent project policy,
and [Pipelines](../pipelines/overview) for exact internal execution order.

<InfoBox variant="tip" title="A reliable operating pattern">

Inspect repository state, run validation, preview consequential operations with
global `--dry-run`, execute normally only after the preview is understood, and
verify both local and remote results afterward.

</InfoBox>

<Section title="Start with Repository State">

<Terminal title="Reusable preflight" language="bash">

{`git status --short --branch
git diff
git diff --staged
git remote -v
custy validate`}

</Terminal>

These checks answer four questions before Custy mutates anything: which branch
is active, which changes exist, which changes are staged, and where remote
operations can go.

</Section>

---

<InfoBox variant="warning" title="Dry-run is a preview, not a guarantee">

Dry-run suppresses supported mutations, while discovery, validation, file
reads, configuration resolution, and remote selection can still run. Read the
[Dry Run concept](../concepts/dry-run) for the exact boundary.

</InfoBox>
