## Goal

Use Release when an approved version should be applied, documented, committed,
tagged, and pushed. The profile validates release prerequisites and ends after
push; it does not invoke Full's experimental finalization stage.

<InfoBox variant="danger" title="A release is durable and non-transactional">

File updates, a commit, a local tag, and one or more remote pushes can complete
before a later failure. Custy does not roll those effects back as one unit.

</InfoBox>

<Section title="Post-Release Verification">

<Terminal title="Verify local release state" language="bash">

{`git status --short --branch
git log -1 --decorate --stat
git tag --points-at HEAD
git remote -v`}

</Terminal>

Also verify the branch and tag through each repository host or an appropriate
fetch-and-compare process. A successful push to one destination does not prove
that every configured destination completed.

</Section>

---

<InfoBox variant="warning" title="Release is the recommended default over Full">

Full adds experimental post-push branch transitions and cleanup. Use Release
unless you deliberately require and understand that additional boundary.

</InfoBox>
