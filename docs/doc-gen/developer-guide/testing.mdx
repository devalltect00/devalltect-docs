## Overview

Doc Gen tests should use temporary projects and explicit output paths. Print and
analyze must remain read-only; generate may write only the selected document;
and dry-run must not create its output directory or invoke the writer.

<InfoBox variant="tip" title="Test rendering separately from persistence">

In-memory rendering can run during dry-run. Assert the rendered result at the
renderer boundary and assert non-invocation at the writer boundary.

</InfoBox>

<Section title="Focused Validation">

<Terminal title="Focused pytest examples" language="bash">

{`# CLI behavior and concise errors
python -m pytest tests/cli

# Initialization builders and execution

python -m pytest tests/core/initialize

# Generated-output and command dry-run boundaries

python -m pytest tests/test_dry_run.py

# Make, Docker, Compose, and metadata contracts

python -m pytest tests/test_developer_workflows.py tests/unit/config`}

</Terminal>

On Windows, use a repository-local `--basetemp` when the system temporary
directory has inherited ACL restrictions.

</Section>

<Section title="Pre-Commit Quality Gates">

Doc Gen runs Ruff lint fixes, Ruff formatting, Black, trailing-whitespace
cleanup, and final-newline correction through pre-commit.

<Terminal title="Pre-commit checks" language="bash">

{`make pre-commit-validate
make pre-commit-run-staged
make pre-commit-run`}

</Terminal>

Repository and tool exclusions protect inactive historical and personal
reference files from automatic changes.

</Section>
