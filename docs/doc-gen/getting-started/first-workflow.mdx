<Section title="Install a Reviewed Release">

Authorized users can install from the private GitLab PyPI registry with the
project ID and a deploy token limited to `read_package_registry`.

<Terminal title="Private GitLab package" language="bash">{`python -m venv venv

# Activate the environment, then install one reviewed package version.

python -m pip install \
 --index-url "https://<deploy-user>:<deploy-token>@gitlab.com/api/v4/projects/<project-id>/packages/pypi/simple" \
 "doc-gen==1.0.2"

doc-gen --version`}</Terminal>

A Git tag such as `v1.0.0-rc.1` becomes PEP 440 package version `1.0.0rc1`.
Use `doc-gen==1.0.0rc1` when deliberately testing that release candidate.
This package is private; do not commit tokens or credential-bearing index URLs.

</Section>

<Section title="Install from a Source Checkout">

<Terminal title="Environment" language="bash">{`python -m venv venv
python -m pip install .
doc-gen --version`}</Terminal>

</Section>

<Terminal title="Safe first workflow" language="bash">{`cd /path/to/project
doc-gen init --dry-run
doc-gen init

# Read-only inspection

doc-gen structure print .
doc-gen structure analyze .

# Preview the resolved target and output path

doc-gen structure generate . --output docs/project_structure.md --dry-run

# Generate only after reviewing the preview

doc-gen structure generate . --output docs/project_structure.md`}</Terminal>

<InfoBox variant="warning" title="One selected output">

Live `structure generate` writes only its resolved Markdown output. Existing
unrelated documentation remains outside the command's write scope.

</InfoBox>

<InfoBox variant="note" title="Runtime">
  Python 3.9+ compatibility; Python 3.14 standard runtime
</InfoBox>
