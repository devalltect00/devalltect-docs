# Design Patterns

## Overview

This document describes the architectural and design patterns used throughout Reflow.

The goal is not to apply patterns for their own sake, but to improve:

```text
Maintainability
Testability
Readability
Extensibility
```

---

# Architectural Philosophy

Reflow follows:

```text
Simple
Explicit
Layered
Configuration Driven
```

The project prefers:

```text
Small focused components
Clear responsibilities
Incremental refactoring
```

instead of large monolithic implementations.

---

# Layered Architecture

Reflow is organized into layers.

```text
CLI
 ↓
Resolver
 ↓
Core
 ↓
Service
 ↓
Executor
 ↓
External Tools
```

Each layer has a dedicated responsibility.

---

# Command Pattern

Location:

```text
app/cli/commands/
```

Examples:

```text
reflow init
reflow tags convert
reflow tags replay
reflow dockerize
```

Each command acts as an entry point into the system.

Responsibilities:

```text
Accept user input
Display output
Delegate work
```

Avoid:

```text
Business logic inside commands
```

---

# Resolver Pattern

Location:

```text
resolver.py
```

Purpose:

```text
Convert CLI input
Load configuration
Apply defaults
Validate options
```

Example:

```text
CLI Input
     ↓
Resolver
     ↓
Resolved Model
```

Benefits:

```text
Thin commands
Centralized validation
Testable option resolution
```

---

# Configuration Object Pattern

Location:

```text
models.py
```

Examples:

```text
DockerizeConfig
ConvertConfig
ReplayConfig
```

Purpose:

```text
Bundle related settings
Pass structured data
Avoid long parameter lists
```

Instead of:

```python
function(
    value1,
    value2,
    value3,
    value4,
)
```

prefer:

```python
function(config)
```

---

# Service Pattern

Location:

```text
app/core/
```

Examples:

```text
GitService
DockerService
ReleaseService
```

Purpose:

```text
Encapsulate business operations
Provide reusable behavior
```

Benefits:

```text
Reusability
Testability
Separation of concerns
```

---

# Executor Pattern

Purpose:

```text
Isolate external tool execution
```

Examples:

```text
Git Executor
Docker Executor
GitHub CLI Executor
```

Workflow:

```text
Service
   ↓
Executor
   ↓
External Tool
```

Benefits:

```text
Mockable
Testable
Replaceable
```

---

# Factory Pattern

Examples:

```python
create_git_service()

create_docker_service()
```

Purpose:

```text
Centralize object creation
Hide implementation details
```

Benefits:

```text
Cleaner commands
Cleaner dependency management
```

---

# Presenter Pattern

Location:

```text
app/ui/
```

Purpose:

```text
Separate presentation from logic
```

Workflow:

```text
Business Logic
      ↓
Result Model
      ↓
Presenter
      ↓
Console Output
```

Benefits:

```text
Reusable UI
Consistent UX
Simpler testing
```

---

# Data Transfer Object Pattern

Examples:

```text
Config Models
Result Models
Summary Models
```

Purpose:

```text
Move structured data between layers
```

Benefits:

```text
Type safety
Readability
Reduced coupling
```

---

# Dependency Direction

Preferred:

```text
CLI
 ↓
Resolver
 ↓
Core
 ↓
Service
 ↓
Executor
```

Avoid:

```text
Executor
 ↓
CLI
```

Dependencies should always flow downward.

---

# Validation Pattern

Validation belongs in:

```text
Resolvers
Configuration Models
```

Examples:

```text
Invalid provider
Missing image name
Invalid tag format
```

Avoid validation scattered across multiple layers.

---

# Error Handling Pattern

Preferred:

```python
except ReflowError:
    ...
```

Avoid:

```python
except Exception:
    ...
```

unless absolutely necessary.

Benefits:

```text
Predictable failures
Clearer debugging
Safer code
```

---

# Configuration-Driven Pattern

Many Reflow features are controlled through:

```text
config.toml
```

Example:

```toml
[tool.reflow.docker]

provider = "github"
```

Benefits:

```text
Reduced CLI complexity
Reusable defaults
Consistent behavior
```

---

# Dry Run Pattern

Supported by multiple commands.

Purpose:

```text
Preview actions
Avoid accidental changes
```

Workflow:

```text
Resolve
Validate
Display Plan
Stop
```

instead of:

```text
Resolve
Validate
Execute
```

Benefits:

```text
Safer operations
Better user confidence
```

---

# Testing-Friendly Design

Most architectural decisions support:

```text
Unit Testing
Integration Testing
Mocking
Refactoring
```

Examples:

```text
Resolver Tests
Service Tests
Command Tests
```

---

# Patterns We Intentionally Avoid

Reflow intentionally avoids:

```text
Global State
Singletons
Deep Inheritance Trees
Hidden Side Effects
```

Preferred alternatives:

```text
Dependency Injection
Factories
Composition
Configuration Objects
```

---

# Summary

The most important architectural patterns in Reflow are:

```text
Layered Architecture
Command Pattern
Resolver Pattern
Service Pattern
Executor Pattern
Factory Pattern
Presenter Pattern
Configuration-Driven Design
```

Together these patterns help keep Reflow maintainable, testable, and easy to evolve as new features are added.
