# Architecture Workflow

## Overview

This document describes the internal architecture of Reflow and the execution flow from CLI commands to external tooling.

The architecture follows a layered design that provides:

- Separation of concerns
- Testability
- Dependency injection
- Maintainability
- Extensibility

The goal is to keep CLI commands thin, business logic centralized, and external tool interactions isolated.

---

# Architecture Overview

```text
CLI
 ↓
Resolver
 ↓
Core
 ↓
Service
 ↓
Executor
 ↓
External Tool
```

Example:

```text
Typer Command
        ↓
Resolver
        ↓
ConfigLoader
        ↓
Orchestrator / TagConverter
        ↓
GitService / DockerService / GitHubService
        ↓
Executor
        ↓
git / docker / gh
```

# Layer Responsibilities

## CLI Layer

Location:

```text
app/cli/
```

Examples:

```text
app/cli/commands/reflow/tags/convert/command.py
app/cli/commands/reflow/tags/replay/command.py
app/cli/commands/reflow/dockerize/command.py
```

Responsibilities:

```text
✓ Parse CLI arguments
✓ Display progress
✓ Display results
✓ Display errors
✓ Handle user interaction
```

Should NOT contain:

```text
✗ Git business logic
✗ Docker business logic
✗ GitHub business logic
✗ Shell execution
✗ Configuration parsing
```

CLI commands should remain thin.

Workflow:

```text
Parse
  ↓
Resolve
  ↓
Execute
  ↓
Display
```

---

## Resolver Layer

Location:

```text
app/cli/commands/**/resolver.py
```

Examples:

```text
app/cli/commands/reflow/tags/convert/resolver.py
app/cli/commands/reflow/tags/replay/resolver.py
app/cli/commands/reflow/dockerize/resolver.py
```

Responsibilities:

```text
✓ Load configuration
✓ Validate inputs
✓ Resolve defaults
✓ Build models
✓ Merge CLI and config values
```

Workflow:

```text
CLI Options
      ↓
ConfigLoader
      ↓
Resolver
      ↓
Command Model
```

Resolvers act as the bridge between the CLI layer and the core layer.

---

## Configuration Layer

Location:

```text
app/config/config_loader.py
```

Responsibilities:

```text
✓ Read TOML configuration
✓ Provide nested access
✓ Resolve defaults
✓ Validate required values
```

Resolution priority:

```text
CLI Value
      ↓
Config File
      ↓
Default Value
```

Example:

```bash
reflow tags convert --delete-old
```

Overrides:

```toml
delete_old = false
```

because CLI values always win.

---

## Core Layer

Location:

```text
app/core/reflow/
```

Examples:

```text
orchestrator.py
tag_converter.py
tag_processor.py
```

Responsibilities:

```text
✓ Business workflows
✓ Application orchestration
✓ Domain logic
✓ Cross-service coordination
```

Should NOT contain:

```text
✗ Rich rendering
✗ Typer code
✗ Direct shell execution
```

The core layer is the heart of the application.

# Dependency Direction

Dependencies always flow downward:

```text
CLI
 ↓
Resolver
 ↓
Core
 ↓
Service
 ↓
Executor
```

Never:

```text
Executor
 ↓
CLI
```

Never:

```text
Service
 ↓
Typer
```

Never:

```text
Core
 ↓
Rich UI
```

This rule keeps the architecture maintainable and testable.

```text
CLI
  ↓
Mock Resolver

Resolver
  ↓
Mock ConfigLoader

Core
  ↓
Mock Services

Services
  ↓
Mock Executors
```

Benefits:

```text
✓ Fast tests
✓ Isolated tests
✓ Deterministic tests
✓ High coverage
```

# Design Principles

## Single Responsibility

Each class should have one responsibility.

Examples:

```text
GitService
    = Git operations

DockerService
    = Docker operations

GitHubService
    = GitHub operations

TagConverter
    = Tag conversion
```

---

## Dependency Injection

Dependencies are injected through constructors.

Example:

```python
GitService(executor)
```

instead of:

```python
GitService()
```

creating executors internally.

This improves testability.

---

## Thin CLI

Commands should:

```text
Parse
Resolve
Execute
Display
```

and nothing more.

---

## Rich Core

Business rules belong in:

```text
app/core/
```

not:

```text
app/cli/
```

# Current Core Components

## Orchestrator

Location:

```text
app/core/reflow/orchestrator.py
```

Responsibilities:

```text
✓ Replay workflows
✓ Coordinate services
✓ Aggregate results
```

---

## TagConverter

Location:

```text
app/core/reflow/tag_converter.py
```

Workflow:

```text
1. Read SHA from old tag
2. Read message from old tag
3. Generate new tag
4. Create temporary message file
5. Create annotated tag
6. Optionally delete old local tag
7. Return new tag
```

Responsibilities:

```text
✓ PEP440 → SemVer conversion
✓ Preserve SHA
✓ Preserve annotations
✓ Preserve tag messages
```

---

## TagProcessor

Location:

```text
app/core/reflow/tag_processor.py
```

Responsibilities:

```text
✓ Version parsing
✓ Version transformation
✓ Tag normalization
```
