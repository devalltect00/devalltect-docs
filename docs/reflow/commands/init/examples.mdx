# Init Examples

## Overview

This guide contains practical examples for:

```bash
reflow init
```

Use these examples as a reference when setting up a new project or recovering existing files.

---

# Quick Start

Initialize a new project:

```bash
reflow init
```

Result:

```text
✓ Create configuration files
✓ Create project metadata
✓ Create templates
✓ Create examples
```

Recommended for:

```text
New users
New repositories
First-time setup
```

---

# Configuration Only

Create configuration files without generating additional resources.

Command:

```bash
reflow init --mode config
```

Typical output:

```text
config.toml
```

Recommended when:

```text
You only need configuration.
```

---

# Templates Only

Generate template resources.

Command:

```bash
reflow init --mode templates
```

Recommended when:

```text
Templates were deleted.
Templates need to be restored.
```

---

# Examples Only

Generate example resources.

Command:

```bash
reflow init --mode examples
```

Recommended when:

```text
You want sample files.
You need example configurations.
```

---

# Generate Everything

Explicitly generate all available resources.

Command:

```bash
reflow init --mode all
```

Result:

```text
config.toml
__version__.py
templates/
examples/
```

Recommended for:

```text
New projects
Complete project setup
```

---

# Preview Changes

Preview initialization without creating files.

Command:

```bash
reflow init --dry-run
```

Workflow:

```text
Build Initialization Plan
         ↓
Display Planned Changes
         ↓
No Files Written
```

Recommended before:

```text
Large migrations
Existing repositories
Production repositories
```

---

# Overwrite Existing Files

Force replacement of existing files.

Command:

```bash
reflow init --force
```

Workflow:

```text
Existing File
       ↓
Overwrite
       ↓
New File
```

Use carefully.

---

# Ask Before Overwriting

Prompt before modifying files.

Command:

```bash
reflow init --ask
```

Workflow:

```text
File Exists
      ↓
Prompt User
      ↓
Create or Skip
```

Recommended when:

```text
Working in existing repositories
Reviewing changes manually
```

---

# Combine Options

Configuration-only preview:

```bash
reflow init \
    --mode config \
    --dry-run
```

Result:

```text
Preview configuration creation
No files written
```

---

Configuration-only with confirmation:

```bash
reflow init \
    --mode config \
    --ask
```

Result:

```text
Prompt before creating files
```

---

Force complete initialization:

```bash
reflow init \
    --mode all \
    --force
```

Result:

```text
Overwrite existing resources
Create missing resources
```

---

# First-Time User Workflow

Recommended workflow:

## Step 1

Initialize project:

```bash
reflow init
```

---

## Step 2

Review generated configuration:

```text
config.toml
```

---

## Step 3

Update project-specific values.

Example:

```toml
[tool.reflow.docker]

provider = "github"
```

---

## Step 4

Run desired commands:

Convert tags:

```bash
reflow tags convert
```

Replay releases:

```bash
reflow tags replay
```

Build images:

```bash
reflow dockerize
```

---

# Recover Missing Configuration

If:

```text
config.toml
```

was deleted accidentally:

```bash
reflow init --mode config
```

This recreates the configuration without generating unrelated resources.

---

# Existing Repository Workflow

Recommended:

Preview:

```bash
reflow init --dry-run
```

Review planned changes.

Then:

```bash
reflow init --ask
```

Approve changes interactively.

---

# Team Onboarding Workflow

When joining an existing project:

```bash
reflow init
```

Then:

```text
Review generated files
Review config.toml
Run project commands
```

This provides a consistent setup process across the team.

# Summary

The most common command is:

```bash
reflow init
```

For existing repositories:

```bash
reflow init --dry-run
```

is recommended first.

Initialization is typically performed once per project and prepares the project for the rest of the Reflow workflow.
