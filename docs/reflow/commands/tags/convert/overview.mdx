# Convert Version Tags

## Overview

The `reflow tags convert` command converts Git tags from PEP 440 format to Semantic Versioning (SemVer) format.

This command is useful when migrating projects, standardizing version schemes, or preparing repositories for tooling that expects Semantic Versioning.

---

# Why This Command Exists

Different ecosystems use different version formats.

Python projects commonly use:

```text
v1.0.0rc1
v1.0.0b2
v1.0.0a3
```

which follow PEP 440 conventions.

Many release tools, container registries, CI/CD systems, and automation workflows prefer Semantic Versioning.

Examples:

```text
v1.0.0-rc.1
v1.0.0-beta.2
v1.0.0-alpha.3
```

The convert command bridges those formats.

---

# What This Command Does

The command:

1. Reads existing Git tags.
2. Detects PEP 440 version tags.
3. Converts them into SemVer equivalents.
4. Creates new Git tags.
5. Optionally removes the original tags.

Example:

Before:

```text
v1.0.0rc1
v2.0.0b2
v3.0.0a3
```

After:

```text
v1.0.0-rc.1
v2.0.0-beta.2
v3.0.0-alpha.3
```

---

# What This Command Does NOT Do

The command does not:

- Modify commits
- Change commit history
- Build Docker images
- Publish releases
- Replay release automation
- Create GitHub releases

If you need release recovery:

```bash
reflow tags replay
```

If you need container publishing:

```bash
reflow dockerize
```

---

# Current Conversion Direction

Current implementation supports:

```text
PEP 440
      ↓
Semantic Versioning
```

Examples:

```text
v1.0.0rc1
      ↓
v1.0.0-rc.1
```

```text
v1.0.0b1
      ↓
v1.0.0-beta.1
```

```text
v1.0.0a1
      ↓
v1.0.0-alpha.1
```

---

# Current Limitations

The current implementation does not support:

```text
Semantic Versioning
        ↓
PEP 440
```

Examples:

```text
v1.0.0-rc.1
      ↓
v1.0.0rc1
```

This conversion direction is not currently available.

# Typical Use Cases

## Python Project Migration

A Python project historically used:

```text
v1.0.0rc1
```

but new tooling expects:

```text
v1.0.0-rc.1
```

Convert tags to align with modern release tooling.

---

## Container Publishing

Many Docker workflows work more naturally with SemVer tags.

Convert tags before publishing images.

---

## Release Standardization

Teams may want all repositories to follow a single versioning strategy.

Convert existing repositories into a consistent format.

# Inputs

The command uses:

- Existing Git tags
- Git repository metadata

---

# Outputs

The command produces:

- New Semantic Version tags
- Optional cleanup of old tags

Example:

Input:

```text
v2.0.0rc1
```

Output:

```text
v2.0.0-rc.1
```

---

# Delete Old Tags

Optional behavior:

```bash
reflow tags convert --delete-old
```

Workflow:

```text
Create new tag
        ↓
Delete original tag
```

Without:

```bash
reflow tags convert
```

Workflow:

```text
Create new tag
        ↓
Keep original tag
```

This is the safest migration strategy.
