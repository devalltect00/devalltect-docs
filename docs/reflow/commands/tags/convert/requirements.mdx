# Convert Version Tags Requirements

## Overview

Before running:

```bash
reflow tags convert
```

ensure the required tools, repository configuration, and tag formats are available.

Unlike replay operations, conversion creates new Git tags and may optionally remove existing tags.

Understanding the requirements helps prevent accidental repository changes.

---

# Required Software

## Git

Git is required.

The converter reads existing tags and creates new tags using Git commands.

Verify installation:

```bash
git --version
```

Example:

```text
git version 2.50.0
```

---

# Repository Requirements

## Valid Git Repository

Conversion must be executed inside a Git repository.

Example:

```bash
cd my-project

reflow tags convert
```

---

## Existing Tags

The repository must contain tags.

Verify:

```bash
git tag
```

Example:

```text
v1.0.0
v1.1.0rc1
v2.0.0b1
```

---

## Tag Read Access

The current user must be able to read repository tags.

Verify:

```bash
git tag
```

If tags cannot be listed, conversion cannot proceed.

---

## Tag Creation Access

The current user must be able to create tags.

Verify:

```bash
git tag test-tag
git tag -d test-tag
```

If tag creation fails, conversion will fail.

---

# Supported Formats

Current implementation supports PEP 440 pre-release tags.

---

## Release Candidate

Input:

```text
v1.0.0rc1
```

Output:

```text
v1.0.0-rc.1
```

---

## Beta

Input:

```text
v1.0.0b1
```

Output:

```text
v1.0.0-beta.1
```

---

## Alpha

Input:

```text
v1.0.0a1
```

Output:

```text
v1.0.0-alpha.1
```

---

# Unsupported Formats

The following examples are currently unsupported.

---

## Custom Tags

Example:

```text
release-candidate
```

---

## Development Tags

Example:

```text
dev-build
```

---

## Arbitrary Naming Schemes

Example:

```text
build-123
release-2025
preview
```

---

## Reverse Conversion

Not currently supported:

```text
SemVer
    ↓
PEP 440
```

Example:

```text
v1.0.0-rc.1
```

cannot currently be converted back into:

```text
v1.0.0rc1
```

---

# Annotated Tags

Annotated tags are fully supported.

Example:

```text
Tag:
    v1.0.0rc1

Message:
    Release Candidate 1
```

The conversion workflow preserves:

```text
✓ Tag message
✓ Commit SHA
✓ Tag metadata
```

---

# Lightweight Tags

Lightweight tags are also supported.

Example:

```text
v1.0.0rc1
```

without additional annotation metadata.

---

# Recommended Preparation

Before converting tags:

---

## Step 1 — List Existing Tags

```bash
git tag
```

Review current tag formats.

---

## Step 2 — Create Backup

Recommended:

```bash
git tag > tags-backup.txt
```

This creates a simple record of existing tags.

---

## Step 3 — Run Dry Run

Recommended:

```bash
reflow tags convert --dry-run
```

Verify expected conversions.

---

## Step 4 — Convert Without Cleanup

Recommended:

```bash
reflow tags convert
```

This preserves original tags.

Example:

Before:

```text
v1.0.0rc1
```

After:

```text
v1.0.0rc1
v1.0.0-rc.1
```

---

## Step 5 — Remove Old Tags Later

After validation:

```bash
reflow tags convert --delete-old
```

This is the safest migration workflow.

---

# Common Problems

## Not a Git Repository

Problem:

```text
fatal: not a git repository
```

Solution:

Run conversion inside a Git repository.

---

## No Tags Found

Problem:

```text
No tags found
```

Solution:

Verify:

```bash
git tag
```

---

## Unsupported Tag Format

Problem:

```text
Tag skipped
```

Possible cause:

```text
release-candidate
preview
build-123
```

These formats are not currently supported.

---

## Tag Already Exists

Problem:

```text
Tag already exists
```

Example:

```text
v1.0.0-rc.1
```

already exists before conversion.

Solution:

Review existing repository tags before running conversion.

✓ Backup created
✓ Dry run completed
