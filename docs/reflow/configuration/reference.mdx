## Resolution and ownership

When a setting has a matching CLI option, Reflow resolves it in this order:

1. Explicit CLI argument
2. `.config/reflow/config.toml`
3. Internal default

The file created by `reflow init` belongs to the target project. Review it
before committing it, and do not place credentials or tokens in repository
URLs or image names.

<InfoBox variant="warning" title="Configure either path or URL—not both">

Within `[tool.reflow.repository]`, keep only one active target form. If both
`path` and `url` are present, Reflow reports a configuration error. Omitting
both falls back to the current working directory unless an explicit CLI target
is supplied.

</InfoBox>

<Section title="Repository and Git">

<PropertyTable
    title="Target settings"
    items={[
        {property: <code>repository.path</code>, type: "path", defaultValue: ".", description: "Existing local directory. Relative values resolve from the invocation directory."},
        {property: <code>repository.url</code>, type: "Git URL", defaultValue: "unset", description: "Remote repository materialized in a managed temporary clone. Do not embed credentials."},
        {property: <code>git.default_remote</code>, type: "string", defaultValue: "origin", description: "Remote name used for remote tag replacement and release-recovery pushes."},
    ]}
/>

| Command | `path` target | `url` target | Persistent scope |
| --- | --- | --- | --- |
| `reflow init` | Supported | Rejected | Project configuration files |
| `reflow tags convert local` | Supported | Rejected | Local tag refs only |
| `reflow tags convert remote` | Uses the checkout's remote | Uses a temporary clone | Guarded atomic remote push |
| `reflow releases recover` | Uses the checkout's remote | Uses a temporary clone | Delete and re-push selected remote tags |
| `reflow dockerize` | Uses the checkout as source | Uses a temporary clone as source | Docker and registry operations |

Registry values such as `github.image` and `gitlab.image` never select the Git
repository.

</Section>

<InfoBox variant="note" title="Dry-run can still read and log">

Read-only Git or provider discovery and temporary-clone setup may execute in a
dry run. Diagnostic logging may also write to the configured log file; the
workflow's persistent project, remote, Docker, and registry mutations remain
simulated.

</InfoBox>

<Section title="Tag Conversion">

<PropertyTable
    title="[tool.reflow.cli.tags.convert]"
    items={[
        {property: <code>target_format</code>, type: "semver | pep440", defaultValue: "semver", description: "Destination format shared by local and remote tag conversion when --to is omitted."},
        {property: <code>yes</code>, type: "boolean", defaultValue: "false", description: "Bypass the live replacement confirmation after the full plan is displayed. Dry-run never prompts."},
    ]}
/>

The same defaults feed `reflow tags convert local` and
`reflow tags convert remote`; the selected subcommand still controls whether
local or remote refs can change.

</Section>

<Section title="Release Recovery and the Deprecated Alias">

<PropertyTable
    title="[tool.reflow.cli.releases.recover]"
    items={[
        {property: <code>delay</code>, type: "integer >= 0", defaultValue: "2", description: "Seconds between selected remote tag re-push operations."},
        {property: <code>only_stable</code>, type: "boolean", defaultValue: "false", description: "Exclude prerelease tags when selecting releases to recover."},
        {property: <code>limit</code>, type: "integer >= 1 | unset", defaultValue: "unlimited", description: "Maximum number of selected missing-release tags."},
    ]}
/>

`--yes` for `reflow releases recover` is intentionally CLI-only. Recovery
checks GitHub releases, then deletes and re-pushes selected remote tags to
retrigger tag-based CI/CD; it does not create release records through an API.

<PropertyTable
    title="[tool.reflow.cli.tags.replay] (deprecated)"
    items={[
        {property: <code>delay</code>, type: "integer >= 0", defaultValue: "2", description: "Legacy fallback when the canonical recovery delay is not configured."},
        {property: <code>only_stable</code>, type: "boolean", defaultValue: "false", description: "Legacy fallback for the canonical stable-only filter."},
        {property: <code>limit</code>, type: "integer >= 1 | unset", defaultValue: "unlimited", description: "Legacy fallback for the canonical recovery limit."},
    ]}
/>

Keep legacy values only while migrating existing configuration. New
configuration and automation should use `[tool.reflow.cli.releases.recover]`
and `reflow releases recover`.

</Section>

<Section title="Docker and Registry Images">

<PropertyTable
    title="Container publishing"
    items={[
        {property: <code>docker.provider</code>, type: "github | gitlab | both", defaultValue: "github", description: "Select which configured registry destinations reflow dockerize publishes to."},
        {property: <code>docker.keep_local_images</code>, type: "boolean", defaultValue: "false", description: "Keep all built tag images locally instead of removing non-latest images after push."},
        {property: <code>github.image</code>, type: "image name", defaultValue: "template placeholder", description: "GHCR destination, for example ghcr.io/acme/project. Required for github or both."},
        {property: <code>gitlab.image</code>, type: "image name", defaultValue: "template placeholder", description: "GitLab Container Registry destination. Required for gitlab or both."},
    ]}
/>

`reflow dockerize` has no command-specific provider or image flags in Reflow
1.0.0; configure these values in TOML. Live mode builds and pushes one image
per repository tag, tags the latest ordered tag as `latest`, and may remove
non-latest local images.

</Section>

<Section title="Minimal Target Examples">

<Terminal title="Local target" language="toml">

{`[tool.reflow.repository]
path = "../project"

[tool.reflow.cli.tags.convert]
target_format = "semver"
yes = false`}

</Terminal>

<Terminal title="Remote URL target" language="toml">

{`[tool.reflow.repository]
url = "https://github.com/acme/project.git"

[tool.reflow.git]
default_remote = "origin"`}

</Terminal>

Do not combine the `path` and `url` examples in one active configuration.

</Section>

<InfoBox variant="note" title="Use exact supported keys">

Unknown or misspelled keys do not replace supported CLI options or defaults.
Compare the generated file with the packaged Reflow 1.0.0 template when
upgrading an existing project-owned configuration.

</InfoBox>
