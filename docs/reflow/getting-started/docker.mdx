<Section title="Published Image Tags">

Stable releases publish four coordinated references to the same image:

| Tag    | Example  | Behavior                                                                     |
| ------ | -------- | ---------------------------------------------------------------------------- |
| Exact  | `v1.0.2` | Immutable release selection; recommended for CI and reproducible automation. |
| Minor  | `v1.0`   | Moves to the newest stable patch in the 1.0 line.                            |
| Major  | `v1`     | Moves to the newest stable release in the 1.x line.                          |
| Latest | `latest` | Moves to the newest stable Reflow release.                                   |

<Terminal title="Pull Reflow" language="bash">

{`docker pull ghcr.io/devalltect00/reflow:v1.0.2
docker pull ghcr.io/devalltect00/reflow:v1.0
docker pull ghcr.io/devalltect00/reflow:v1
docker pull ghcr.io/devalltect00/reflow:latest`}

</Terminal>

<InfoBox variant="warning" title="Prereleases are exact-only">

A prerelease such as `v1.0.0-rc.1` publishes only its exact tag. It never
updates `v1.0`, `v1`, or `latest`.

</InfoBox>

</Section>

<Section title="Run Safely">

Running `--help` does not require a mounted repository. Operational commands
must receive the intended repository explicitly. Mounting a checkout exposes
real files and Git metadata to the container, so preview consequential work
with Reflow's global `--dry-run` option first.

<Terminal title="Verify the image" language="bash">

{`docker run --rm ghcr.io/devalltect00/reflow:v1.0.2 --help`}

</Terminal>

<InfoBox variant="note" title="Help is independent of the mounted project">

Reflow v1.0.2 resolves project-specific source settings only when an operation
needs them. Running the container with no command or with `--help` therefore
works from repositories that do not contain a `/workspace/app` directory.

</InfoBox>

<InfoBox variant="info" title="This is separate from reflow dockerize">

These tags identify the container used to run Reflow itself. The
`reflow dockerize` command builds or publishes images for a selected target
repository and follows that repository's configured image destination.

</InfoBox>

</Section>
