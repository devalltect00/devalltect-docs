<InfoBox variant="note" title="Runtime requirement">

Reflow requires Python 3.14 or newer. Keep the Reflow installation separate
from the repository it will operate on; target the repository explicitly when
the current directory is ambiguous.

</InfoBox>

<Section title="Install from the Private GitLab Registry">

Reviewed releases are published as private Python packages in the project's
GitLab PyPI registry. Ask a maintainer for the GitLab project ID and a deploy
token limited to `read_package_registry`.

<Terminal title="Install an authorized package version" language="bash">

{`python -m venv venv

# Activate the environment, then install one reviewed package version.

python -m pip install \
 --index-url "https://<deploy-user>:<deploy-token>@gitlab.com/api/v4/projects/<project-id>/packages/pypi/simple" \
 "git-reflow==1.0.1"

reflow --version`}

</Terminal>

<InfoBox variant="warning" title="Package name and command name differ">

Use `git-reflow` in pip. The installed command is `reflow`. A Git tag such as
`v1.0.0-rc.1` is published with the canonical PEP 440 package version
`1.0.0rc1`, so an authorized RC installation uses
`git-reflow==1.0.0rc1`.

</InfoBox>

This is a private registry, not public PyPI. Never commit a token or a
credential-bearing index URL. The source-checkout method below remains valid
when private-registry access is unavailable.

</Section>

<Section title="Install from a Reviewed Source Checkout">

<Terminal title="Create an isolated environment" language="bash">

{`python -m venv venv

# Activate with the command for your shell:

# Windows PowerShell: .\\venv\\Scripts\\Activate.ps1

# POSIX shell: source venv/bin/activate

python -m pip install .
reflow --version`}

</Terminal>

</Section>

<Terminal title="Initialize and preview" language="bash">

{`reflow -C /path/to/project init
git -C /path/to/project tag --list
reflow --dry-run -C /path/to/project tags convert local --to semver`}

</Terminal>

<InfoBox variant="warning" title="Do not add --yes until the plan is understood">

Dry-run never prompts. In live mode, keep the confirmation prompt during
interactive use. Reserve `--yes` for reviewed automation or an already-reviewed
replacement plan.

</InfoBox>
