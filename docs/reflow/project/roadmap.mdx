# Reflow Roadmap

## Overview

This document describes the current state of Reflow, planned improvements, future ideas, and intentionally unsupported features.

The roadmap helps contributors understand where the project is today and where it is expected to evolve.

---

# Vision

Reflow treats Git tags as the source of truth for releases.

Everything else flows from those tags:

```text
Git Tags
    ↓
Release Recovery
    ↓
Version Standardization
    ↓
Container Publishing
```

The long-term goal is to provide a consistent release-management workflow that works across multiple ecosystems and providers.

# Planned Features

These features are considered realistic short-term improvements.

---

## Tag Filtering

Allow processing only matching tags.

Example:

```bash
reflow tags convert \
    --match "v2.*"
```

Benefits:

```text
✓ Faster processing
✓ Safer migrations
✓ Better control
```

---

## Single Tag Processing

Example:

```bash
reflow tags convert \
    --tag v2.0.0rc1
```

---

## Tag Range Processing

Example:

```bash
reflow dockerize \
    --from v1.0.0 \
    --to v2.0.0
```

# Out Of Scope

The following features are intentionally outside the project's current goals.

---

## Dockerfile Generation

Reflow expects an existing Dockerfile.

Not planned:

```text
Generate Dockerfiles
```

---

## Kubernetes Deployment

Reflow stops after publishing images.

Not planned:

```text
kubectl apply
helm install
```

---

## Infrastructure Provisioning

Not planned:

```text
Terraform
CloudFormation
Pulumi
```

---

## CI/CD Pipeline Generation

Not planned:

```text
Generate GitHub Actions
Generate GitLab CI
Generate Jenkinsfiles
```

# Long-Term Direction

The long-term direction is:

```text
Git Tags
      ↓
Release Recovery
      ↓
Version Management
      ↓
Artifact Publishing
```

with provider-specific implementations hidden behind a stable core architecture.

# Success Criteria

The project should continue to prioritize:

```text
✓ Simplicity
✓ Testability
✓ Predictable behavior
✓ Small focused commands
✓ Clear documentation
```

over feature count.
