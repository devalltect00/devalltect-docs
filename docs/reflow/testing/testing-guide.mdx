# Testing Guide

## Overview

This guide explains how testing works in Reflow.

It covers:

- Testing philosophy
- Running tests
- Coverage
- Test organization
- Writing new tests
- Refactoring safely

This document is intended for contributors and maintainers.

---

# Testing Philosophy

Reflow prioritizes:

```text id="v8q3tm"
Behavior
Reliability
Maintainability
```

Tests should verify:

```text id="k4m7rp"
What the system does
```

rather than:

```text id="u9q2tn"
How the system is implemented
```

---

# Core Principles

## Test Behavior

Preferred:

```text id="f3v8pk"
Convert tag correctly
Replay release correctly
Build image correctly
```

Avoid:

```text id="j7q4tm"
Internal implementation details
```

unless absolutely necessary.

---

## Preserve Behavior During Refactoring

When refactoring:

```text id="m2v9rp"
Tests should continue to pass.
```

If behavior changes unexpectedly:

```text id="z5q3tn"
A test should fail.
```

---

## Keep Tests Readable

A test should explain:

```text id="p8v4pk"
What is being tested
Why it matters
Expected result
```

# Running Tests

Run all tests:

```bash id="h4m7tn"
pytest
```

---

Run with verbose output:

```bash id="d9q2rp"
pytest -v
```

---

Run coverage:

```bash id="x3v8tm"
pytest --cov=app
```

---

Show missing coverage:

```bash id="j6m4pk"
pytest --cov=app --cov-report=term-missing
```

---

# Running Specific Tests

Run a directory:

```bash id="w8q3tn"
pytest tests/core/git/
```

---

Run a file:

```bash id="n2v9rp"
pytest tests/core/git/test_service.py
```

---

Run a single test:

```bash id="r5q4tm"
pytest tests/core/git/test_service.py::test_get_all_tags
```

---

# Preferred Test Naming

Preferred:

```python id="g7m3tn"
def test_convert_tag() -> None:
    ...
```

---

More descriptive:

```python id="v2q8rp"
def test_convert_tag_preserves_message() -> None:
    ...
```

---

Avoid:

```python id="r4v7tm"
def test_1() -> None:
    ...
```

---

# Test Structure

Recommended pattern:

```python id="k8q2pk"
def test_example() -> None:
    """
    Verify expected behavior.
    """

    # Arrange

    # Act

    # Assert
```

---

# Mocking

Use mocks when interacting with:

```text id="z3v9rp"
Git
GitHub CLI
Docker
Filesystem
```

Goals:

```text id="m6q4tn"
Fast tests
Reliable tests
No external dependencies
```

---

# Example

Instead of:

```text id="x8v2pk"
Real Docker build
```

prefer:

```text id="c5q7rp"
Mock Docker executor
```

during unit testing.

# Refactoring Workflow

Recommended process:

```text id="h9v3tm"
Write Test
      ↓
Refactor
      ↓
Run Tests
      ↓
Verify Behavior
```

This approach minimizes risk.

# Continuous Improvement

Testing should evolve alongside the codebase.

When bugs are discovered:

Recommended workflow:

```text id="u3q4rp"
Bug Found
      ↓
Add Test
      ↓
Fix Bug
      ↓
Verify Test
```

This prevents regressions.

# Recommended Workflow

Before opening a pull request:

```bash id="n7v2tm"

pytest
```

All commands should pass successfully.

