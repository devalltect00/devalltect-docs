# Getting Started

## Overview

This guide helps you get started with Reflow.

By the end of this guide, you will:

- Install Reflow
- Initialize a project
- Configure Reflow
- Run your first command

---

# What Is Reflow?

Reflow is a CLI tool for:

```text
Git Tag Replay
Version Conversion
Docker Release Automation
```

Reflow treats Git tags as the source of truth for releases.

---

# Installation

Clone the repository:

```bash
git clone <repository-url>
```

Enter the project:

```bash
cd reflow
```

Create a virtual environment:

```bash
python -m venv .venv
```

Activate the environment:

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -e .
```

---

# Verify Installation

Check that Reflow is available:

```bash
reflow --help
```

You should see the main help screen.

---

# Step 1 — Initialize Project

Run:

```bash
reflow init
```

Purpose:

```text
Create project configuration
Create project metadata
Create templates
Create examples
```

Documentation:

```text
docs/init/
```

---

# Step 2 — Review Configuration

Open:

```text
config.toml
```

Review project-specific values.

Example:

```toml
[tool.reflow.docker]

provider = "github"
```

---

# Step 3 — Choose A Workflow

Reflow commands are independent.

Run only the commands you need.

---

## Convert Tags

Purpose:

```text
PEP440 → SemVer
```

Command:

```bash
reflow tags convert
```

Documentation:

```text
docs/tags/convert/
```

---

## Replay Releases

Purpose:

```text
Recover release automation
```

Command:

```bash
reflow tags replay
```

Documentation:

```text
docs/tags/replay/
```

---

## Dockerize Releases

Purpose:

```text
Build and publish Docker images
```

Command:

```bash
reflow dockerize
```

Documentation:

```text
docs/dockerize/
```

---

# Recommended Workflow

For repositories migrating from PEP 440 and publishing containers:

```text
reflow init
      ↓
Edit config.toml
      ↓
reflow tags convert
      ↓
reflow tags replay
      ↓
reflow dockerize
```

# Summary

The most common workflow is:

```text
Install
    ↓
Init
    ↓
Configure
    ↓
Run Commands
```

For most users, the first command should be:

```bash
reflow init
```

which prepares the project for the rest of the Reflow workflow.
