## Gambaran umum

Custy memakai arsitektur berlapis yang pragmatis. Command publik berada di CLI layer, sedangkan operasi utama dinyatakan sebagai pipeline step yang mendelegasikan pekerjaan ke workflow engine dan layanan terfokus.

<InfoBox variant="info" title="Lapisan tanggung jawab, bukan batas folder yang kaku">
  Lapisan ini menjelaskan alur dependensi aktif. Beberapa modul core masih memakai enum
  CLI atau helper presentasi Rich, sehingga dokumentasi ini menggambarkan implementasi
  saat ini tanpa mengklaim isolasi yang belum ada.
</InfoBox>

<Section title="Batas penting">

- Pipeline berjalan berurutan dan tidak transaksional; efek sebelumnya tidak otomatis di-rollback.
- Internal profile dan registered step tidak otomatis menjadi pilihan publik `custy run`.
- Konfigurasi menjadi milik project setelah initialization dan loader melakukan cache per process.
- Version generation, sinkronisasi version file, dan tag sorting adalah tanggung jawab terpisah.

</Section>
