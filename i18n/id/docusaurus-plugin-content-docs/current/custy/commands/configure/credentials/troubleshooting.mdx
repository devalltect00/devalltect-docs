## Configured File Tidak Ada

<Section compact>
  Jalankan `status`. Missing file bukan malformed file: Custy mencoba configured source
  berikutnya dan dapat memakai approved interactive prompt. Mount directory tujuan ke
  `/run/secrets/custy` atau set `CUSTY_CREDENTIALS_DIR`.
</Section>

---

## Provider Enabled tetapi File Missing

<Section compact>
  `Enabled: yes` berasal dari mounted project configuration. `Token file: missing`
  berarti current container tidak dapat melihat external file. Jalankan kembali `status`
  dengan credential bind mount yang sama seperti saat setup. Environment source tetap
  dapat menampilkan `missing` ketika valid file source sudah tersedia.
</Section>

---

## File Setup Memperingatkan Input Dapat Terlihat

<Section compact>
  Container dijalankan tanpa controllable terminal. Gunakan `-i` dan `-t`, biasanya
  ditulis sebagai `docker run --rm -it`. Versi Custy saat ini menolak unsafe
  hidden-input fallback dan menjelaskan invocation yang diperlukan.
</Section>

---

## Username dan Password Prompt Menghilang

<Section compact>
  Image lama dapat menangkap terminal streams saat Git menunggu input sehingga active
  prompt terlihat seperti freeze. Rebuild atau pull current image. Custy sekarang
  menghentikan progress display dan memberikan direct terminal ownership kepada manual
  Git authentication. Untuk HTTPS, masukkan username dan PAT, bukan account password.
  Menekan Enter dua kali mengirim empty credentials dan menyebabkan authentication
  failure.
</Section>

---

## Token File Tidak Valid

<Section compact>
  Custy berhenti pada symbolic link, directory, oversized data, invalid encoding,
  multiple lines, NUL byte, atau surrounding whitespace. Buat ulang melalui wizard atau
  `set --replace`; jangan melemahkan validation.
</Section>

---

## Local Execution Mengabaikan Configured Token

<Section compact>
  Ini expected saat `container_only = true`. Local execution tetap memakai Git helper
  atau SSH session milik host. Set `container_only = false` hanya jika external fallback
  memang diperlukan secara lokal.
</Section>

---

## Remote Menggunakan SSH

<Section compact>
  Token fallback hanya berlaku pada supported HTTPS hosts. Kelola SSH key, agent
  forwarding, `known_hosts`, dan file permissions melalui Git/SSH.
</Section>

---

## Non-Interactive Push Langsung Gagal

<Section compact>
  Dengan `fail_non_interactive = true`, Custy menetapkan `GIT_TERMINAL_PROMPT=0` ketika
  prompt tidak dapat dijawab. Sediakan configured file atau environment source, terutama
  di CI.
</Section>

---

## Authentication Tetap Ditolak

<Section compact><Terminal>{`custy configure credentials status
custy configure credentials test --remote origin
git remote get-url origin`}</Terminal>

Periksa exact host, HTTPS protocol, account username, PAT scopes, expiration,
repository membership, dan branch permissions. Custy mempertahankan Git failure
details tanpa menampilkan token.

</Section>

<InfoBox variant="danger" title="Rotate exposed credentials">
  Jika token masuk ke source control, URL, shell history, logs, atau image layer, revoke
  dan ganti token di provider sebelum melanjutkan.
</InfoBox>
