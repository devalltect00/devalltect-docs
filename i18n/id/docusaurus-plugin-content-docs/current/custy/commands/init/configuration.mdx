## Ringkasan

Salah satu tujuan utama `custy init` adalah membuat file configuration khusus
proyek.

Custy tidak mengharuskan setiap command-line option diberikan setiap kali.
Banyak perilaku dapat dikonfigurasi satu kali dan digunakan kembali secara
otomatis oleh command berikutnya.

<InfoBox
    variant="tip"
    title="Project Configuration"
>

Configuration yang dibuat merupakan bagian dari proyek, bukan aplikasi Custy.

Dengan menyimpan file configuration dalam version control, setiap kontributor
dapat menggunakan default yang sama dengan mudah.

</InfoBox>

---

<Section
    title="Configuration File"
>

Setelah init, file configuration utama berada di:

<Terminal>

{`
.config/custy/config.toml
`}

</Terminal>

Command Custy berikutnya otomatis memuat file ini ketika tersedia.

</Section>

<Section
    title="Prinsip Configuration"
>

Custy dirancang dengan prinsip bahwa perilaku proyek sebaiknya dapat
disesuaikan, bukan di-hard-code.

Configuration yang dibuat menyediakan lokasi terpusat untuk menentukan
preferensi proyek satu kali, sehingga tim tidak perlu mengulang
command-line options yang sama pada setiap operasi.

Pendekatan ini meningkatkan konsistensi, tetapi tetap memungkinkan setiap
command meng-override nilai configuration ketika diperlukan.

</Section>

---

<InfoBox
    variant="note"
    title="Configuration yang Dapat Berkembang"
>

File configuration sengaja disusun dalam bagian-bagian yang logis.

Ketika Custy memperoleh kemampuan baru, grup configuration tambahan dapat
ditambahkan tanpa mengubah keseluruhan struktur file.

</InfoBox>

---

<Section
    title="Hubungan dengan Command-Line Options"
>

Command-line options selalu memiliki prioritas lebih tinggi daripada nilai
configuration.

Ketika option tidak diberikan, Custy mencoba menentukan nilainya dari project
configuration sebelum menggunakan default bawaan.

Dengan demikian, proyek dapat menetapkan default yang sesuai sekaligus tetap
memberikan fleksibilitas kepada pengguna untuk meng-override nilai saat
diperlukan.

</Section>
