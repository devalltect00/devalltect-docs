## Ringkasan

Command `custy init` menyiapkan proyek yang sudah ada agar dapat digunakan
bersama **Custy**.

Command ini tidak mengubah riwayat Git proyek atau menjalankan release
workflow. Sebagai gantinya, command ini membuat workspace proyek yang dapat
dikonfigurasi di bawah `.config/custy/`. File yang dibuat memungkinkan Anda
menyesuaikan perilaku Custy tanpa mengubah aplikasi itu sendiri.

Menjalankan `custy init` adalah langkah pertama yang direkomendasikan saat
mulai menggunakan Custy pada repositori baru maupun yang sudah ada.

<InfoBox
    variant="tip"
    title="Direkomendasikan"
>

Walaupun Custy menyediakan default bawaan yang masuk akal dan banyak command
dapat bekerja tanpa konfigurasi khusus proyek, `custy init` sangat
direkomendasikan karena membuat file konfigurasi serta template yang dapat
disesuaikan dengan workflow proyek Anda.

</InfoBox>

<Section
    title="Kapan Command Ini Digunakan?"
>

Anda biasanya perlu menjalankan `custy init` ketika:

- Menyiapkan Custy di sebuah proyek untuk pertama kali.
- Menambahkan Custy ke repositori Git yang sudah ada.
- Membuat configuration khusus proyek.
- Membuat ulang template default setelah upgrade Custy.
- Menyiapkan repositori untuk digunakan oleh seluruh tim.

Pada sebagian besar proyek, `custy init` dijalankan sekali saat setup awal.
Setelah itu, configuration yang dibuat cukup diperbarui seiring perkembangan
proyek.

</Section>

---

<Section
    title="Yang Tidak Dilakukan Command Ini"
>

Berbeda dengan workflow commands, `custy init` **tidak**:

- Membuat commit.
- Membuat Git tag.
- Melakukan push ke remote repository.
- Membuat release.
- Mengubah riwayat Git.
- Menjalankan release pipeline.

Tanggung jawabnya hanya menyiapkan proyek untuk workflow Custy berikutnya.

</Section>

---

<Section
    title="Workspace Proyek"
>

Setelah init selesai, proyek Anda memiliki workspace Custy khusus.

<Terminal>

{`your-project/
└── .config/
    └── custy/
        ├── config.toml
        └── templates/
            ├── backups/
            ├── changelog/
            ├── examples/
            ├── commit-message.txt
            └── tag-message.txt`}

</Terminal>

Workspace ini memisahkan configuration khusus proyek dari default internal
Custy, sehingga perilaku dapat disesuaikan tanpa mengubah aplikasi.

</Section>

---

<Section
    title="Mengapa Perlu Menjalankan Init?"
>

Custy sudah dilengkapi perilaku default yang masuk akal.

Artinya, init **direkomendasikan**, tetapi tidak mutlak diwajibkan.

Tanpa menjalankan `custy init`, Custy menggunakan default bawaannya.

Menjalankan `custy init` memberi fleksibilitas tambahan karena proyek dapat
menentukan sendiri:

- configuration
- templates
- preferences
- struktur direktori

Pendekatan ini menyeimbangkan kemudahan dan kemampuan customization.

</Section>

---

<InfoBox
    variant="note"
    title="Customization"
>

Karena file yang dibuat merupakan bagian dari proyek, bukan aplikasi Custy,
file tersebut dapat ditinjau, disimpan dalam version control, dan dibagikan
kepada kontributor lain di repositori yang sama.

</InfoBox>

- Jalankan workflow yang telah ditentukan.
- Sesuaikan configuration dan template yang dibuat.
