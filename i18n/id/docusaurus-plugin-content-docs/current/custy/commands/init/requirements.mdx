## Ringkasan

Sebelum menjalankan `custy init`, pastikan proyek dan development environment
Anda sudah siap.

Custy menyediakan default yang masuk akal dan dirancang untuk bekerja dengan
setup minimal. Namun, memenuhi rekomendasi berikut akan memberikan pengalaman
terbaik serta mempermudah pengelolaan workflow selanjutnya.

<InfoBox
    variant="tip"
    title="Direkomendasikan"
>

Sebagian besar proyek hanya perlu menjalankan `custy init` satu kali. Setelah
init, file configuration dan template yang dibuat dapat disesuaikan dengan
workflow tim Anda.

</InfoBox>

<Section
    title="Metode Instalasi yang Didukung"
>

Pilih sumber instalasi dan environment yang sudah ditinjau serta paling sesuai
dengan proyek Anda:

- instalasi Python normal dari source checkout;
- wheel atau source distribution yang dilampirkan pada rilis terpilih;
- Git tag atau commit yang di-pin;
- instalasi source editable untuk kontributor Custy; atau
- image Docker yang di-build secara lokal dari Dockerfile Custy.

Lihat [Installation](../../getting-started/installation) untuk metode native dan
[Docker](../../getting-started/docker) untuk requirements container.

Perilaku command tetap sama untuk setiap metode instalasi.

</Section>

---

<Section
    title="Contoh"
>

Contoh berikut menjalankan init pada proyek saat ini.

<Terminal>

{`custy init`}

</Terminal>

Jika Anda telah mem-build image production lokal yang didokumentasikan, mount
root proyek yang dimaksud ke `/workspace`:

<Terminal>

{`docker run -it --rm \
    -v "<project>:/workspace" \
    -w /workspace \
    custy-prod:latest \
    init`}

</Terminal>

Image menyertakan Git, Python 3.14, pip, dan Make. Git di host tidak diperlukan
untuk pemanggilan container ini, tetapi proyek yang di-mount harus menyertakan
direktori `.git` agar command Custy berbasis Git dapat menggunakannya nanti.

</Section>

---

<InfoBox
    variant="note"
    title="Keamanan Proyek"
>

Menjalankan `custy init` menyiapkan proyek dengan membuat file configuration
dan template. Command ini tidak membuat commit, mengubah riwayat Git, atau
menjalankan release workflow.

</InfoBox>
