## Ringkasan

Setelah validation selesai, Custy melaporkan apakah proyek memenuhi
requirements untuk workflow berikutnya.

Jika validation menemukan masalah, eksekusi langsung berhenti dan Custy
melaporkan penyebab beserta panduan penyelesaiannya.

<Section title="Validation Berhasil">

Ketika setiap validation step berhasil:

- Repository memenuhi prerequisites yang dikonfigurasi.
- Project resources yang diperlukan tersedia.
- Workflow-oriented commands dapat dilanjutkan.
- Riwayat repository tidak diubah.

Validation yang berhasil hanya memastikan kesiapan. Proses ini tidak membuat
commit, tag, release, atau mengubah proyek.

</Section>

---

<Section title="Validation Gagal">

Ketika validation gagal:

- Validation step saat ini dilaporkan.
- Validation steps berikutnya dilewati.
- Pesan deskriptif menjelaskan masalah.
- Hint yang membantu diberikan selama memungkinkan.

Perilaku fail-fast membantu menemukan dan menyelesaikan masalah sebelum
menjalankan workflow operation yang lebih kompleks.

</Section>

---

<InfoBox variant="tip" title="Baca Hint">

Ketika validation gagal, baca hint yang diberikan sebelum mencoba kembali.
Sebagian besar failure dapat diselesaikan dengan mengikuti tindakan yang
disarankan, seperti menjalankan Git init, membuat templates, atau melakukan
stage terhadap perubahan.

</InfoBox>

---

<Section title="Dry Run">

Jika validation dijalankan sebagai bagian dari workflow dengan global option
`--dry-run`, Custy melaporkan tindakan yang biasanya dilakukan tanpa
menjalankan workflow actions yang mengubah repository.

Dengan demikian, Anda dapat memeriksa workflow readiness sebelum eksekusi
sebenarnya.

</Section>

---

<Section title="Langkah Berikutnya">

Jika validation melaporkan masalah, lanjutkan ke halaman **Troubleshooting**
untuk panduan penyelesaian validation failure yang umum.

</Section>
