## Ringkasan

Sebelum menjalankan **custy validate**, proyek sebaiknya memenuhi beberapa
requirements dasar.

Sebagian besar validation failure terjadi karena satu atau beberapa
prerequisites belum tersedia, bukan karena masalah pada Custy.

<InfoBox variant="tip" title="Tidak Semua Requirement Bersifat Wajib">

Beberapa validation checks bergantung pada project configuration dan workflow.
Commitizen bersifat optional kecuali commit validation provider atau version
strategy secara explicit mewajibkannya. Auto mode menggunakan built-in
validator Custy ketika Commitizen tidak dikonfigurasi atau diinstal.

</InfoBox>

<Section title="Persiapan yang Direkomendasikan">

Sebelum menjalankan validation:

- Buka root directory proyek.
- Pastikan Git sudah diinisialisasi.
- Tinjau configuration `.config/custy/config.toml`.
- Stage perubahan jika Anda akan melanjutkan ke commit workflow.
- Pastikan template files yang diperlukan sudah dibuat.

Langkah tersebut mengurangi kemungkinan validation failure.

</Section>

---

<InfoBox variant="note" title="Validation Otomatis">

Jika workflow biasanya dijalankan melalui `custy run`, Anda umumnya tidak perlu
menjalankan `custy validate` secara manual karena validation dilakukan otomatis
sebelum workflow dilanjutkan.

</InfoBox>

---

<Section title="Apa yang Tidak Diperlukan?">

Validation **tidak** memerlukan:

- Git commit yang sudah ada.
- Git tag yang sudah ada.
- Release yang sudah dipublikasikan.
- Remote push.

Command ini memeriksa kesiapan operasi berikutnya, bukan riwayat proyek.

</Section>
