## Ringkasan

Custy dapat diinstal dari registry GitLab PyPI privat milik proyek, source
checkout, artefak Python yang dilampirkan pada rilis, atau langsung dari
repositori Git. Kontributor sebaiknya menggunakan instalasi editable dengan
grup dependensi development. Docker merupakan alternatif terpisah jika Anda
tidak ingin menginstal Python atau Git langsung di host.

<InfoBox
    variant="info"
    title="Registry privat, bukan PyPI publik"
>

`pip install custy` tanpa konfigurasi index tidak akan menemukan proyek ini di
PyPI publik. Pengguna yang memiliki akses dapat memilih index GitLab privat;
source checkout, artefak rilis, dan revisi Git yang sudah ditinjau tetap
didukung sebagai alternatif.

</InfoBox>

<Section
    title="Metode 1: Instal dari GitLab PyPI Privat"
>

Minta ID proyek GitLab dan deploy token yang hanya memiliki izin
`read_package_registry` kepada maintainer proyek. Kemudian instal satu versi
package yang tepat di environment terisolasi.

<Terminal title="Instal dari registry proyek privat" language="bash">

{`python -m venv venv

# Aktifkan environment, lalu instal satu versi yang sudah ditinjau.
python -m pip install \
  --index-url "https://<deploy-user>:<deploy-token>@gitlab.com/api/v4/projects/<project-id>/packages/pypi/simple" \
  "custy==2.1.1"

custy --version`}

</Terminal>

Tag rilis Git tetap menggunakan SemVer, sedangkan metadata package menggunakan
PEP 440 kanonis. Contohnya, tag `v2.1.0-rc.1` diinstal sebagai
`custy==2.1.0rc1`.

<InfoBox variant="warning" title="Simpan kredensial registry di luar repositori">

Jangan commit deploy token, URL index yang memuat kredensial, atau konfigurasi
pip yang berisi rahasia. Hindari `--extra-index-url` untuk package privat karena
index yang bersaing dapat menimbulkan risiko dependency confusion. Untuk
resolusi dependensi yang benar-benar privat, maintainer proyek juga perlu
meninjau pengaturan package forwarding GitLab.

</InfoBox>

</Section>

<Section
    title="Metode 2: Instal dari Source Checkout"
>

Clone repositori, buat virtual environment, lalu instal package runtime. Ini
adalah cara native yang direkomendasikan jika Anda belum memilih artefak rilis
yang sudah ditinjau.

<Terminal title="Clone dan buat environment" language="bash">

{`git clone https://github.com/devalltect00/Custy.git
cd Custy
python -m venv venv`}

</Terminal>

Aktifkan environment sesuai shell yang Anda gunakan.

<Terminal title="Windows PowerShell" language="powershell">

{`venv\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
python -m pip install .`}

</Terminal>

<Terminal title="Linux atau macOS" language="bash">

{`source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .`}

</Terminal>

</Section>

<Section
    title="Metode 3: Instal Artefak Rilis"
>

Alur rilis Custy dikonfigurasi untuk melampirkan Python wheel dan source
distribution. Buka
[halaman Custy Releases](https://github.com/devalltect00/Custy/releases), pilih
rilis yang sudah ditinjau, lalu pastikan rilis tersebut benar-benar berisi
artefak yang dimaksud sebelum mengunduhnya.

<Terminal title="Instal wheel yang sudah diunduh" language="bash">

{`python -m pip install ./custy-<version>-py3-none-any.whl`}

</Terminal>

<Terminal title="Instal source distribution yang sudah diunduh" language="bash">

{`python -m pip install ./custy-<version>.tar.gz`}

</Terminal>

<InfoBox
    variant="warning"
    title="Jangan mengunci dokumentasi ke satu rilis lama"
>

Ketersediaan artefak dan nomor versi berubah seiring waktu. Gunakan halaman
Releases umum, pilih versi yang dituju secara sengaja, dan verifikasi nama
asset yang ditampilkan oleh rilis tersebut.

</InfoBox>

</Section>

<Section
    title="Metode 4: Instal Langsung dari Git"
>

Jika Anda tidak memerlukan checkout lokal, pip dapat menginstal tag atau commit
Git yang sudah ditinjau ke environment aktif.

<Terminal title="Instal revisi yang sudah ditinjau" language="bash">

{`# Ganti <tag-or-commit> dengan revisi tepat yang sudah Anda tinjau
python -m pip install "git+https://github.com/devalltect00/Custy.git@<tag-or-commit>"`}

</Terminal>

Menghilangkan `@<tag-or-commit>` akan mengikuti branch default repositori dan
menghasilkan instalasi yang kurang reproducible.

</Section>

<Section
    title="Instalasi Editable untuk Developer"
>

Kontributor yang mengembangkan Custy itu sendiri sebaiknya menginstal source
tree dalam mode editable dengan dependensi development yang dinyatakan dalam
`pyproject.toml`.

<Terminal title="Instalasi editable dengan tool development" language="bash">

{`python -m pip install -e ".[dev]"`}

</Terminal>

Gunakan `python -m pip install -e .` hanya jika Anda memerlukan kode runtime
editable tanpa tool development opsional. Tambahkan `docs` saat mengerjakan
source MkDocs lama milik Custy:
`python -m pip install -e ".[dev,docs]"`.

<InfoBox
    variant="tip"
    title="Mengapa menggunakan python -m pip?"
>

Menjalankan pip melalui `python -m pip` memastikan instalasi menggunakan
interpreter Python dari virtual environment yang aktif.

</InfoBox>

</Section>

---

<Section
    title="Helper Makefile Opsional"
>

Makefile repositori dapat membuat environment `venv/` standar dan menjalankan
target instalasi editable. Helper ini ditujukan untuk source checkout Custy
dan memerlukan GNU Make.

<Terminal title="Penyiapan kontributor dengan Make" language="bash">

{`make venv
make upgrade-pip
make install-dev`}

</Terminal>

- `make install` menginstal dependensi runtime dalam mode editable.
- `make install-dev` menambahkan grup dependensi development.
- `make install-all` menambahkan tool development dan dokumentasi lama.
- Make hanya merupakan lapisan bantu; perintah `python -m pip` yang setara
  tetap dapat digunakan tanpa Make.

</Section>

<Section
    title="Masalah Instalasi yang Umum"
>

<InfoBox
    variant="warning"
    title="Versi Python terlalu lama"
>

Jika pip melaporkan versi Python yang tidak kompatibel, instal Python 3.14 atau
lebih baru, buat ulang virtual environment dengan interpreter tersebut, lalu
instal kembali.

</InfoBox>

<InfoBox
    variant="warning"
    title="custy tidak dikenali"
>

Pastikan virtual environment yang dimaksud sudah aktif. Anda juga dapat
menjalankan executable secara langsung, misalnya
`venv\Scripts\custy.exe --help` di Windows, atau menggunakan
`python -m app --help` dari source checkout.

</InfoBox>

<InfoBox
    variant="warning"
    title="Perintah Git tidak tersedia"
>

Instal Git dan pastikan `git --version` berfungsi di shell yang sama. Instalasi
package Python yang berhasil tidak menyediakan executable Git yang diperlukan
oleh alur kerja utama Custy.

</InfoBox>

</Section>
