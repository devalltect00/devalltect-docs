## Ringkasan

Panduan mulai cepat ini menyiapkan repositori tanpa langsung membuat commit,
tag, atau pembaruan remote. Inisialisasi menulis resource proyek, validasi
memeriksa kesiapan, dan perintah pipeline terakhir menggunakan mode dry run
global.

<InfoBox
    variant="tip"
    title="Jalankan perintah dari root proyek"
>

Custy menentukan `.config/custy/`, file versi, template, kondisi Git, dan remote
secara relatif terhadap proyek saat ini. Pastikan working directory sudah benar
sebelum memulai.

</InfoBox>

<Section
    title="Inisialisasi Custy"
>

Jalankan mode inisialisasi default, lalu periksa semua resource yang ditambahkan
atau dilewati.

<Terminal title="Inisialisasi dan periksa" language="bash">

{`custy init
git status --short`}

</Terminal>

Mode default `all` dapat membuat konfigurasi, template, resource contoh, dan
file versi. File yang sudah ada dipertahankan kecuali perilaku force dipilih.
Jika direktori examples sudah ada, Custy tetap menambahkan missing nested
packaged examples tanpa mengganti existing example files.

<Terminal title="Tinjau repository links dan remotes" language="bash">

{`git remote -v

# Edit .config/custy/config.toml, lalu validasi.

custy validate`}

</Terminal>

<InfoBox variant="note" title="Repository URL bukan nama remote">

`tool.custy.changelog.links.repository` adalah URL browser HTTP(S) opsional
untuk links di `CHANGELOG.md`. `default_remote`, `main_remotes`, dan
`backup_remotes` berisi nama Git remote seperti `origin` atau `mirror`.

</InfoBox>

<InfoBox
    variant="warning"
    title="Jangan gunakan force saat peninjauan awal"
>

`custy init --force` dapat menimpa resource yang dibuat. Mulailah dengan
`custy init` dan periksa file yang dilewati sebelum memilih perilaku overwrite.

</InfoBox>

</Section>

<Section
    title="Validasi Repositori"
>

Jalankan validasi setelah meninjau workspace proyek yang dibuat.

<Terminal title="Jalankan pemeriksaan kesiapan" language="bash">

{`custy validate`}

</Terminal>

Validasi memeriksa kondisi repositori dan prasyarat alur kerja, seperti file
yang diperlukan, konfigurasi, resource versi, perubahan yang sudah di-stage,
dan remote. Selesaikan kegagalan yang dilaporkan sebelum melanjutkan ke
pipeline.

</Section>

---

<Section
    title="Pratinjau Pipeline"
>

Gunakan opsi global `--dry-run` sebelum nama perintah. Pratinjau berikut
menentukan profil Dev publik tanpa sengaja menerapkan efek normalnya terhadap
file, commit, dan push.

<Terminal title="Pratinjau development harian" language="bash">

{`custy --dry-run run dev`}

</Terminal>

<InfoBox
    variant="warning"
    title="Pratinjau adalah langkah terakhir panduan mulai cepat"
>

Jangan menghapus `--dry-run` hanya karena perintah berhasil diselesaikan.
Tinjau dahulu tahap yang ditentukan, file pesan, perilaku versi, perubahan Git,
serta tujuan push yang dijelaskan dalam dokumentasi profil Dev.

</InfoBox>

</Section>
