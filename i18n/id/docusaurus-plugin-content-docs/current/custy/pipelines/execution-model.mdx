## Ringkasan

Run command tidak menjalankan profile name secara langsung. Command ini
me-resolve CLI dan project configuration, memperluas selected profile names
menjadi step definitions, membangun concrete step objects, lalu meneruskan satu
shared runtime context melalui resulting sequence.

<InfoBox variant="info" title="Input Order Bukan Execution Order">Untuk multiple profiles, Custy menggunakan global phase priorities: initialization, validation, preparation, generation dan editing, backup dan cleanup, execution, branch cleanup, lalu finalization. Menulis `push commit` tidak memaksa push berjalan sebelum commit.</InfoBox>

<Section title="Exact Ordering Rule">

- Dengan satu recognized profile, Custy memperluas nested profile references dan
  mempertahankan declared sequence. Single result tidak di-sort ulang dengan `STEP_ORDER`.
- Dengan dua atau lebih profiles, Custy memperluas setiap profile, menggabungkan
  steps, mempertahankan first occurrence setiap name, lalu menerapkan stable numeric sort menggunakan `STEP_ORDER`.
- Step tanpa priority entry menerima fallback value `999` saat merged-profile sort.

Lihat [Step Priority and Ordering](./step-order) untuk seluruh 27 entries dan complete worked example.

</Section>

---

<Section title="Shared Runtime Context">Setiap step menerima `GitContext` yang sama. Context menyediakan workflow engine, Git service, optional Commitizen helper, dan mutable runtime values seperti resolved tag, workflow case, serta files yang dipilih untuk staging. Satu step dapat menyiapkan state untuk later step tanpa membuat ulang services.</Section>

---

<Section title="Progress dan Failure Semantics">

Active Run pipeline menampilkan Rich progress indicator dan hanya maju setelah
step berhasil. Saat step menghasilkan exception, Custy menghentikan progress,
mengidentifikasi failed step, melempar ulang error, dan tidak menjalankan later steps.

<InfoBox variant="danger" title="Stopped Pipeline Tidak Di-Roll Back">Earlier file writes, commits, tags, atau pushes mungkin sudah tersedia. Tentukan last successful stage dan periksa local serta remote state sebelum memilih recovery action.</InfoBox>

</Section>
