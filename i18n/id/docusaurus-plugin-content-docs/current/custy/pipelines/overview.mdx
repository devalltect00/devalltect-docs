## Ringkasan

Custy pipeline adalah ordered collection dari registered steps. Public profile
seperti `dev` atau `release` memilih prepared collection; Custy me-resolve
profile tersebut, membangun setiap step, lalu menjalankannya satu per satu.

Bagian ini menjelaskan sistem di balik command. Gunakan [panduan Run
command](../commands/run/overview) untuk syntax, options, examples, dan
troubleshooting CLI.

<InfoBox variant="tip" title="Pilih Jalur yang Sesuai dengan Tujuan Anda">Jika hanya ingin menjalankan Custy, mulai dari [Profiles](./profiles). Untuk meninjau behavior, baca [Execution Model](./execution-model). Untuk berkontribusi pada code, lanjutkan ke [Step System](./step-system).</InfoBox>

<Section title="Public Boundary">

Typed argument `custy run` saat ini hanya menerima `commit`, `tag`, `push`,
`dev`, `release`, dan `full`. Internal resolver profiles digunakan oleh
implementation dan direct commands, tetapi bukan public Run names tambahan.

<Terminal title="Public profile examples" language="bash">{`# Preview daily development pipeline
custy --dry-run run dev

# Jalankan complete release pipeline
custy run release

# Gabungkan dua supported profiles
custy --dry-run run commit push`}</Terminal>

</Section>

---

<Section title="Important Safety Boundary">Pipeline execution bersifat sequential, bukan transactional. Jika step gagal, Custy berhenti dan melaporkan failed step, tetapi tidak otomatis membatalkan changes dari step sebelumnya. Selalu periksa files, Git history, tags, dan remote state sebelum retry.</Section>
