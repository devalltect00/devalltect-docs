## Ringkasan

Profiles mengemas related steps menjadi intentional flows. Tiga focused
profiles membuat commit, tag, atau push. Tiga composite profiles
mengoordinasikan broader development dan release work. Semuanya merupakan
public subset dari resolver catalog yang digunakan direct commands dan nested
pipeline definitions Custy.

<Section title="Complete Resolver Catalog">

20 definitions dalam `PIPELINE_PROFILES` terbagi menjadi empat kelompok:

- **6 public Run profiles** — `commit`, `tag`, `push`, `dev`, `release`, dan `full`.
- **9 direct-command-only profiles** — validation, changelog, version update,
  backup, cleanup, dan initialization profiles yang dipilih focused commands.
- **4 nested validation profiles** — reusable repository, commit, tag, dan remote validation groups.
- **1 defined aggregate** — `cleanup_all`, sedangkan current Cleanup All command
  menjalankan dua focused cleanup profiles secara terpisah.

Buka [Complete Profile Reference](./profile-reference) untuk setiap consumer,
step count, dan exact expanded sequence.

</Section>

---

<Section title="Practical Selection Rules">

- Pilih `commit`, `tag`, atau `push` untuk focused outcome tersebut.
- Pilih `dev` untuk daily commit-and-push tanpa version application dan tag creation.
- Pilih `release` untuk complete versioned publication flow.
- Pilih `full` hanya jika Anda memahami dan membutuhkan branch workflow finalization setelah push.

</Section>

<InfoBox variant="danger" title="Hanya Enam Nama Ini yang Public">
  Active typed Run argument menolak internal names seperti `validate`, `changelog`,
  `apply_version`, backup profiles, cleanup profiles, dan validation subprofiles.
  Gunakan direct commands yang tersedia; jangan dokumentasikan atau script internal
  names sebagai public `custy run` values.
</InfoBox>

<Section title="Direct Command atau Profile?">
  Gunakan direct command untuk command-specific inputs atau satu focused operation.
  Gunakan profile saat Custy harus mengoordinasikan validation, preparation, artifact,
  backup, dan execution stages di sekitarnya. Contohnya, `custy changelog generate`
  adalah supported focused changelog command; `custy run changelog` bukan public Run
  invocation.
</Section>
