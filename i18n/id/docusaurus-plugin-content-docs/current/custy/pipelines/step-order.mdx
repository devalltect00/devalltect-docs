## Ringkasan

`STEP_ORDER` adalah global sort-key map yang digunakan saat Custy menggabungkan
dua atau lebih profiles. Lower values ditempatkan lebih awal. Gaps antar-phase
memberi ruang untuk future steps tanpa renumber seluruh pipeline.

<InfoBox variant="info" title="Priority Mengatur Urutan, Bukan Concurrency">
  Values ini tidak mengatur threads, operating-system priority, timing, atau parallel
  execution. Custy tetap menjalankan satu step pada satu waktu. Number hanya menentukan
  position saat menormalisasi merged profile.
</InfoBox>

<Section title="Worked Example: push + commit">

`custy run push commit` dan `custy run commit push` saat ini dinormalisasi
menjadi 19 steps yang sama. CLI input order tidak memindahkan `push_step`
sebelum validation, preparation, atau `commit_step`.

<InfoBox variant="warning" title="STEP_ORDER adalah Safety-Sensitive Contract">
  Mengubah priority dapat memindahkan validation setelah file writes atau mengubah
  urutan commit, tag, push, cleanup, dan finalization. Contributors harus memperbarui
  resolver tests, profile tests, integration tests, dan reference ini ketika ordering
  berubah.
</InfoBox>
