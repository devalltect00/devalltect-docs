## Baseline saat ini

Halaman-halaman ini menjelaskan **Custy v2.1.0** dan terakhir ditinjau terhadap
source aktif pada **25 Agustus 2026**. Tanggal tersebut mencatat peninjauan
dokumentasi yang disengaja, bukan tanggal edit Git atau deployment otomatis.

<InfoBox variant="info" title="Remote tag diperiksa saat build">

Portal menjalankan `git ls-remote --tags --refs` ketika Docusaurus dimulai atau
dibangun. Portal tidak meminta GitHub dari browser setiap pengunjung. Hasil yang
sudah di-deploy tidak berubah sampai situs dokumentasi dibangun kembali.

</InfoBox>

Custy menggunakan deteksi SemVer otomatis sesuai strategi tag repositori saat ini.

<Section title="Bandingkan Versi yang Terpasang">

<Terminal title="Tampilkan versi Custy yang terpasang" language="bash">

{`custy --version`}

</Terminal>

- Jika perintah menampilkan `2.1.0`, dokumentasi ini adalah baseline yang sesuai.
- Jika versinya lebih lama, gunakan release notes dan tag source versi tersebut
  untuk mengenali fitur yang belum tersedia.
- Jika versinya lebih baru, tinjau rilis setelah `v2.1.0` untuk command, option,
  configuration, perubahan perilaku, dan perbaikan baru.
- Untuk versi pre-release atau post-release, bandingkan versi lengkap, termasuk
  penanda seperti `alpha`, `beta`, `rc`, `dev`, atau `post`.

Gunakan [rilis Custy](https://github.com/devalltect00/Custy/releases) dan
[snapshot source `v2.1.0`](https://github.com/devalltect00/Custy/tree/v2.1.0)
sebagai referensi khusus rilis.

</Section>

### Mode otomatis

```ts title="src/data/projects.ts"
documentation: {
  version: "2.1.0",
  versionTag: "v2.1.0",
  lastReviewed: "2026-08-25",
  releaseUrl: "https://github.com/devalltect00/Custy/releases/tag/v2.1.0",
  statusPath: "/docs/custy/reference/documentation-status",
  freshness: {
    mode: "auto",
    repositoryUrl: "https://github.com/devalltect00/Custy.git",
    tagFormat: "semver",
    releasesUrl: "https://github.com/devalltect00/Custy/releases",
    includePrereleases: false,
    timeoutMs: 10_000,
    fallbackStatus: "unknown",
  },
}
```

### Mode manual

Gunakan mode manual untuk format versi custom, repositori yang tidak dapat
dijangkau environment build, atau proyek yang status rilisnya memerlukan
penilaian manusia.

```ts title="src/data/projects.ts"
freshness: {
  mode: "manual",
  status: "current", // current | outdated | preview
  latestVersionTag: "custom-release-42", // opsional
}
```

<Section title="Aturan Pemilihan Tag">

1. Periksa direct remote tag refs tanpa clone repositori.
2. Hapus `refs/tags/`, buang duplikat peeled `^{}` secara defensif, dan
   pertahankan tag asli untuk tampilan.
3. Terima prefiks `v` konvensional yang opsional.
4. Abaikan tag yang tidak sesuai grammar `semver` atau `pep440` terpilih.
5. Kecualikan prerelease kecuali `includePrereleases` bernilai `true`.
6. Urutkan tag kompatibel menggunakan grammar terpilih, bukan urutan teks.
   Contohnya, `1.10.14` diurutkan setelah `1.10.9` secara benar.
7. Bandingkan versi terbaru yang dinormalisasi dengan baseline dokumentasi.

Grammar tag custom tidak diterima dalam mode otomatis. Pilih mode manual alih-alih
memperkirakan aturan pengurutan custom.

</Section>

<Section title="Penanganan Kegagalan">

- Konfigurasi maintainer yang tidak valid, termasuk format yang tidak didukung,
  baseline tidak valid, URL remote kosong, atau timeout di luar rentang, akan
  menghentikan build dengan pesan yang dapat ditindaklanjuti.
- Git tidak tersedia, kegagalan jaringan, kegagalan autentikasi, dan timeout
  tidak diam-diam menyatakan dokumentasi current. Plugin menggunakan
  `fallbackStatus` dan mencetak peringatan build.
- Pemeriksaan berhasil tanpa tag kompatibel menggunakan fallback yang sama
  dengan kode diagnostik `no-compatible-tags`.
- Detail error remote tetap berada di log build; raw process error tidak
  ditampilkan kepada pengunjung dokumentasi.
- Pemeriksaan remote berjalan satu kali per proyek yang dikonfigurasi pada
  setiap proses Docusaurus, bukan satu kali per halaman.

Untuk repositori private, pastikan environment build dapat mengautentikasi Git
URL yang dikonfigurasi. Jangan menaruh credential atau token langsung di
`src/data/projects.ts`.

</Section>

<Section title="Deployment dan Otomatisasi Rilis">

Deteksi otomatis dievaluasi ketika `yarn start`, `yarn build`, atau perintah
Docusaurus lain memuat plugin. Tag Custy baru tidak mengubah situs statis yang
sudah di-deploy sampai Devalltect Docs dibangun kembali.

Workflow Pages saat ini membangun ulang ketika ada push ke repositori
dokumentasi dan ketika workflow dijalankan manual. Integrasi berikutnya dapat
memicu build dokumentasi dari rilis Custy melalui `repository_dispatch`, atau
workflow terjadwal dapat memeriksa ulang tag secara berkala. Trigger workflow
tersebut terpisah dari freshness resolver.

</Section>

<Section title="Pemeliharaan Dokumentasi">

Maintainer perlu memperbarui baseline pusat ketika rilis Custy mengubah command,
option, configuration, workflow, output, architecture, atau perilaku lain yang
didokumentasikan dan terlihat oleh pengguna. Sinkronisasi lengkap mencakup:

1. Tinjau tag rilis baru dan perilaku source aktif.
2. Perbarui halaman bahasa Inggris yang terdampak.
3. Terapkan perubahan teknis yang sama pada halaman bahasa Indonesia sambil
   mempertahankan nama command, option, path, configuration key, dan code.
4. Ubah versi baseline, tag, URL rilis, dan tanggal terakhir ditinjau.
5. Pastikan `tagFormat` tetap sesuai strategi SemVer repositori.
6. Jalankan freshness tests, type checking, dan production build untuk kedua
   locale.

Notifikasi global membaca satu entri metadata pusat dan hasil resolver saat
build. Notifikasi disembunyikan ketika dokumentasi current dan hanya muncul
ketika pengguna memerlukan konteks preview, outdated, atau kegagalan verifikasi.

</Section>
