<Section title="Kebutuhan dasar">
  Local installation memerlukan Python yang memenuhi project metadata, `pip`, dan Git.
  Virtual environment direkomendasikan. Docker dan Make bersifat optional sesuai
  installation method atau helper yang digunakan.
</Section>

<InfoBox variant="info" title="Authentication berada di luar Custy">
  Push memakai konfigurasi credential Git pada host atau container. Custy tidak
  menyimpan token remote. Pastikan editor eksternal dan encoding terminal juga sesuai
  environment Anda.
</InfoBox>

<Section title="Editor environment variables">

Custy tidak mendefinisikan editor environment variable secara otomatis. Custy
mewarisi variable yang diberikan kepada process-nya dan memeriksa exact name
berikut ketika `tool.custy.editor.prefer_environment = true`:

Hanya `VISUAL` dan `EDITOR` yang menerima editor command. Gunakan uppercase
name secara tepat agar portable. Jika salah satunya kosong, tidak didefinisikan,
atau menunjuk executable yang tidak tersedia, Custy melanjutkan ke candidate
berikutnya yang diizinkan editor policy.

<Terminal title="Atur value sebelum menjalankan Custy" language="bash">

{`# PowerShell
$env:VISUAL = "code --wait"
$env:EDITOR = "notepad"

# POSIX shell

export VISUAL="micro"
export EDITOR="nano"

# Docker

docker run --rm -it -e VISUAL=micro -e EDITOR=nano \
 -v "\${PWD}:/workspace" -w /workspace \
 custy-prod:latest run release`}

</Terminal>

Operating system, shell profile, IDE, Docker/Compose service, atau CI job harus
memberikan value sebelum Custy dijalankan. Custy tidak me-load `.env` file
secara langsung. Custy membaca `VISUAL` dan `EDITOR` ketika workflow mencapai
commit atau tag message editing, sehingga perubahan di terminal lain tidak
mengubah Custy process yang sudah berjalan. Lihat
[Editor Configuration](../configuration/editor) untuk setup examples, accepted
commands, container behavior, dan matrix lengkap `prefer_environment` serta
`allow_fallback`.

Ketika environment precedence aktif, Custy membaca `VISUAL` lalu `EDITOR`,
kemudian mengikuti configured candidates untuk container atau operating system.
Windows me-resolve command shim seperti `code.CMD` sebelum launch. Container
Linux standar menggunakan Micro, Nano, Vim, atau Vi di dalam image dan
memerlukan `-it`; container tidak membuka VS Code atau Notepad yang hanya
terinstal pada host.

</Section>
