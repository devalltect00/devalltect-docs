## Tujuan

Gunakan branch cleanup untuk deliberate repository maintenance setelah merged
atau stale work tidak diperlukan. Active CLI subcommand bersifat plural:
`custy cleanup branches`.

<InfoBox variant="danger" title="Matching Branches Dapat Dihapus Locally dan Remotely">
  Active cleanup request defaults ke local deletion dan remote deletion pada `origin`.
  Public command belum menyediakan switches untuk mengubah deletion flags atau remote.
  Perlakukan setiap normal run sebagai operasi yang dapat menghapus kedua copies.
</InfoBox>

<Terminal title="Narrow merged-branch cleanup" language="bash">{`git fetch --all --prune
git branch --all

custy --dry-run cleanup brancheses \
 --prefix feature/ \
 --merge-status merged \
 --max-age 30d`}</Terminal>
Pada PowerShell, letakkan command dalam satu line atau gunakan PowerShell
continuation syntax, bukan Bash backslashes di atas.

</Section>

<InfoBox variant="tip" title="Empty Prefixes adalah Safe No-Op">
  Jika prefixes tidak di-resolve dari CLI atau project configuration, tidak ada eligible
  branches. Tambahkan narrow prefixes secara deliberate; jangan gunakan broad prefixes
  hanya agar command memilih sesuatu.
</InfoBox>

<Section title="Jika Wrong Branch Terhapus">
  Hentikan cleanup tambahan. Jika last commit SHA diketahui dan object masih tersedia
  locally, buat ulang local branch dengan standard Git recovery tools, review, lalu push
  hanya jika remote branch juga perlu dipulihkan. Jika commit tidak diketahui, periksa
  reflog dan repository-host history. Recovery bersifat manual karena Custy tidak
  menyimpan branch deletion undo journal.
</Section>
