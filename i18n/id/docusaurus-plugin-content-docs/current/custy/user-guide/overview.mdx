## Ringkasan

Panduan ini mengatur Custy berdasarkan real tasks, bukan individual command
options. Setiap journey menjelaskan persiapan, command atau profile yang harus
dipilih, hal yang dapat berubah, cara verifikasi success, dan pemeriksaan saat
run berhenti di tengah proses.

Gunakan [Command Reference](../commands/overview) untuk seluruh options,
[Configuration](../configuration/overview) untuk persistent project policy,
dan [Pipelines](../pipelines/overview) untuk exact internal execution order.

<InfoBox variant="tip" title="Reliable Operating Pattern">
  Periksa repository state, jalankan validation, preview consequential operations dengan
  global `--dry-run`, jalankan normally hanya setelah preview dipahami, lalu verifikasi
  local dan remote results.
</InfoBox>

<Section title="Mulai dari Repository State">
  <Terminal title="Reusable preflight" language="bash">{`git status --short --branch
git diff
git diff --staged
git remote -v
custy validate`}</Terminal>
  Checks ini menjawab empat pertanyaan sebelum Custy memutasi apa pun: branch mana yang
  active, changes apa yang tersedia, changes mana yang staged, dan tujuan remote
  operations.
</Section>

<InfoBox variant="warning" title="Dry-Run adalah Preview, Bukan Guarantee">
  Dry-run mencegah supported mutations, sedangkan discovery, validation, file reads,
  configuration resolution, dan remote selection tetap dapat berjalan. Baca [Dry Run
  concept](../concepts/dry-run) untuk exact boundary.
</InfoBox>
