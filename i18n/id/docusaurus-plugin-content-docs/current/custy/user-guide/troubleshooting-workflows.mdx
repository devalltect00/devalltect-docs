## Prinsip Pertama

Failed Custy pipeline belum tentu untouched pipeline. Earlier steps mungkin
sudah generate atau edit files, prune backups, stage changes, membuat commit
atau tag, atau update satu atau lebih remotes.

<InfoBox variant="danger" title="Jangan Memulai Recovery dengan Rerun Semuanya">
  Temukan failed step dan last durable effect terlebih dahulu. Full retry dapat
  bertabrakan dengan existing commit atau tag, menduplikasi work, atau publish ke remote
  yang sudah berhasil.
</InfoBox>

<Section title="Perbaiki Diagnostic Output">
  Global options ditempatkan sebelum command group.
  <Terminal title="Diagnostic invocations" language="bash">{`custy --debug run release
custy --log-level DEBUG run dev
custy --debug cleanup brancheses --prefix feature/`}</Terminal>
  Gunakan debug output untuk memahami resolution dan execution, tetapi jangan sertakan
  secrets, tokens, atau sensitive remote credentials saat membagikan logs.
</Section>

<InfoBox
  variant="warning"
  title="Dry-Run Setelah Correction Tidak Membuktikan Rollback"
>
  Corrected dry-run mem-preview next execution dari current state. Ini tidak membatalkan
  atau menyembunyikan effects milik failed run. Periksa ulang state sebelum dan sesudah
  preview.
</InfoBox>

<Section title="Escalate Ketika State Tidak Jelas">
  Berhenti dan minta bantuan teammate atau repository administrator sebelum menghapus
  commits atau tags, force-pushing, mengubah shared branches, restore remote branches,
  atau rewrite published release history. Pertahankan logs dan current state saat
  recovery decision ditinjau.
</Section>
