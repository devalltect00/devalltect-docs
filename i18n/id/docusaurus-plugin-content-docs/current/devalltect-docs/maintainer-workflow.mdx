# Alur Kerja Maintainer

Pemeliharaan portal dimulai dari proyek sumber, bukan dari asumsi tentang
perilakunya. Tinjau versi aplikasi terkait sebelum mengubah perintah,
konfigurasi, persyaratan, panduan keamanan, atau contoh.

## Alur Konten

1. Konfirmasi versi proyek sumber dan perilaku yang terlihat oleh pengguna.
2. Perbarui halaman kanonis berbahasa Inggris yang terdampak.
3. Perbarui halaman Bahasa Indonesia yang setara tanpa menerjemahkan kontrak teknis literal.
4. Perbarui metadata proyek terpusat ketika versi, URL release, tanggal peninjauan, teknologi, atau pratinjau berubah.
5. Tinjau navigasi, cross-link, dan halaman status dokumentasi.
6. Jalankan formatting, pengujian freshness, type checking, dan build kedua locale.
7. Saat file container berubah, validasi Compose dan kedua mode runtime Docker.
8. Tinjau halaman terdampak pada lebar desktop dan mobile sebelum rilis.

## Publikasi Rilis

GitHub Pages dan GitLab Pages memublikasikan portal dari branch default. Tag
rilis tidak menggantikan kedua deployment Pages tersebut; tag membuat halaman
Release terkait setelah sumber yang diberi tag lolos validasi.

Buat tag Semantic Version beranotasi dari pesan rilis yang telah ditinjau:

```bash
git tag -a v1.0.0 -F .config/custy/templates/tag-message_release-version.txt
git push <github-remote> v1.0.0
git push <gitlab-remote> v1.0.0
```

Kedua provider mempertahankan seluruh pesan tag beranotasi sebagai catatan utama
Release publik. Workflow menambahkan bagian Release Information yang dihasilkan
secara otomatis, berisi versi, versi package portal, versi Node.js, jenis rilis,
path proyek provider, dan tautan ke commit persis yang diberi tag. Judul Release
membedakan tag alpha, beta, release candidate, prerelease lainnya, dan stabil.
GitLab mengharuskan tag rilis dilindungi.

Sebagai contoh, rilis stabil diakhiri dengan blok yang dihasilkan seperti ini:

```markdown
---

## 📅 Release Information

- Version: `v1.0.0`
- Portal Package Version: `1.0.0`
- Node.js Version: `20`
- Release Type: `stable`
- Project: `devalltect00/devalltect-docs`
- Commit: [abc12345](provider-specific-commit-url)
```

Workflow rilis tidak memublikasikan package npm, image container, atau salinan
kedua dari site statis. Ketidakcocokan versi package dilaporkan di GitHub tetapi
tidak memblokir rilis dokumentasi historis karena package portal ini bersifat
privat dan bukan package npm yang dipublikasikan.

## Gambar Pratinjau Proyek

Homepage dan setiap landing page proyek menggunakan satu screenshot
representatif yang sama:

```text
static/img/project-previews/custy.png
static/img/project-previews/path-header-scanner.png
static/img/project-previews/doc-gen.png
static/img/project-previews/reflow.png
```

Gunakan PNG untuk output terminal agar teks kecil tetap jelas. Ambil semua
gambar dengan rasio 16:9 yang sama; `1600 × 900` direkomendasikan. Tampilkan
banner yang mudah dikenali bersama output bantuan atau ringkasan yang berguna.
Hapus kredensial, token, path pribadi, URL repositori privat, dan riwayat
terminal yang tidak terkait.

Komponen screenshot menyediakan ukuran responsif, teks alternatif, lazy
loading, dan fallback yang aksesibel. Fallback mencegah aset yang belum selesai
merusak halaman, tetapi bukan pengganti gambar rilis final.

## Artefak Dokumentasi yang Dihasilkan

Custy mengelola `CHANGELOG.md`, sedangkan Doc Gen mengelola
`docs/project_structure.md`. Regenerasikan file tersebut melalui tool
masing-masing dan jangan mengedit bagian yang dihasilkan secara manual.

Dokumen struktur proyek dikecualikan dari Prettier karena format outputnya
dikelola oleh Doc Gen. File tersebut tetap divalidasi oleh pengujian repositori
dan build produksi Docusaurus. Gunakan path berhuruf kecil pada konfigurasi dan
Git agar Windows dan Linux mengarah ke file yang sama. Docker sengaja
mengecualikan `.config/`; validasinya memeriksa artefak yang dilacak, tautan, dan
batas formatter, sedangkan pemeriksaan konfigurasi dijalankan dalam konteks CI
repositori normal.

## Batas Peninjauan

- Jaga komponen bersama tetap umum dan biarkan setiap proyek mempertahankan arsitektur informasinya.
- Utamakan komponen serta variabel tema yang tersedia daripada kode presentasi sekali pakai.
- Jaga makna Bahasa Inggris dan Bahasa Indonesia tetap selaras.
- Jangan publikasikan rilis stabil dengan gambar pratinjau proyek yang belum tersedia atau teks fallback yang rusak.
- Jangan edit output `.docusaurus/` atau `build/` yang dihasilkan otomatis.

## Validasi

Jalankan pemeriksaan Yarn yang didokumentasikan setelah perubahan konten atau UI:

```bash
yarn test:documentation-freshness
yarn typecheck
yarn build
```

Agregat non-mutating yang setara adalah:

```bash
yarn validate
```

Saat konfigurasi Docker, Compose, atau Nginx berubah, jalankan juga:

```bash
make c-config
make c-build-all
make c-check
```

Tinjau site development aktif di
`http://localhost:3000/devalltect-docs/` dan pratinjau produksi immutable di
`http://localhost:8080/devalltect-docs/`. Validasi container tidak boleh
memublikasikan image atau menggantikan deployment Pages.

Jalankan juga pemeriksaan pre-commit yang dikonfigurasi dan konfirmasi output
kedua locale berhasil dibangun tanpa error route, link, anchor, atau rendering
MDX.
